# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

tsumugi: a Misskey multi-column desktop client (Krile-like UX) built on Tauri v2. Rust core (`src-tauri/`) owns all Model-layer logic; the Svelte frontend (`frontend/`) is View/ViewModel only. Design docs live in `docs/design/` — `docs/design/misskey-multicolumn-client-design.md` is the authoritative design doc; if any other doc conflicts with it, the design doc wins. User-facing documentation lives in `docs/guide/user-guide.md`.

Frontend visual conventions (border-radius/font-size/icon-size/focus-visible scales) are codified in `docs/design/style-guide.md` — check it before adding new UI, don't invent one-off values (e.g. `rounded-[Npx]`).

Operation E2E tests (Playwright/tauri-driver against a throwaway Docker Compose Misskey instance) live in `e2e/` — see `e2e/README.md` for setup and run order, not covered here.

`llama.cpp` (the `local-translate` feature, on by default) is built from C++ and an unrestrained build exhausts memory: a plain 16-way parallel build OOM-killed unrelated apps (Issue #603). `src-tauri/.cargo/config.toml` caps cmake at 4 jobs (measured: 4 concurrent compilations). If memory is tight, also set `CARGO_BUILD_JOBS=4` and run under `systemd-run --user --scope -p MemoryMax=10G -p MemoryHigh=8G`. Never put the build output (`CARGO_TARGET_DIR`) in `/tmp` (tmpfs = RAM). To build llama.cpp for Android locally (`cargo check --lib --target <abi>`), put the NDK's `toolchains/llvm/prebuilt/linux-x86_64/bin` on `PATH` and set `ANDROID_NDK_ROOT` (and `ANDROID_NDK_HOME` / `NDK_HOME`) plus `CC_<target>` / `CXX_<target>` / `AR_<target>` (e.g. `CC_aarch64_linux_android=<bin>/aarch64-linux-android26-clang`); cc-rs cannot find the NDK clang otherwise (`cargo tauri android build` sets the compiler variables itself, but **not** `ANDROID_NDK_ROOT`). **Always export `ANDROID_NDK_ROOT=<r27c>` for Android builds:** `llama-cpp-sys-2`'s `build.rs` ignores `NDK_HOME` / `ANDROID_NDK_HOME` and, if `ANDROID_NDK` / `ANDROID_NDK_ROOT` / `NDK_ROOT` are all unset, silently compiles llama.cpp with the newest NDK under the SDK (this machine also has NDK 30). The link succeeds, but the app then crashes at startup with `dlopen failed: cannot locate symbol "_ZNSt6__ndk113__hash_memoryEPKvm"` (libc++ 21 headers vs. the r27c static libc++). (The build script also reads `CARGO_NDK_ANDROID_NDK` after those three, which is what `cargo ndk` sets.) Also export `ANDROID_PLATFORM=android-26` (= minSdk): without it llama.cpp is compiled at API 28. Both builds had no strong undefined libc symbol missing at API 26 (`getrandom` / `copy_file_range` are weak), so this is hygiene, not a crash fix. The build script does re-run when the variable changes (it emits `rerun-if-env-changed`), but the CMake build tree under `target/` is reused and keeps the objects compiled with the old NDK (observed), so run `cargo clean -p llama-cpp-sys-2 -p llama-cpp-2 --target <triple>` after fixing it, and check the result with `scripts/check-android-libcxx.sh <path to libtsumugi_lib.so> <NDK>/toolchains/llvm/prebuilt/linux-x86_64/bin/llvm-nm` (CI runs it too). To skip the C++ build entirely, use `--no-default-features --features custom-protocol` (local translation then reports `LOCAL_UNSUPPORTED`). On Windows, `llama-cpp-2` is a git dependency whose `llama.cpp` submodule has paths up to 195 characters, so with the default `CARGO_HOME` (`C:\Users\<name>\.cargo`) the checkout fails with `path too long` (MAX_PATH 260). Use a short one, e.g. `setx CARGO_HOME C:\c` (CI does this in `local-translate-build.yml` / `release.yml` / `nightly.yml`). On macOS, `tauri build` compiles C++ with `-mmacosx-version-min=<bundle.macOS.minimumSystemVersion>` (Tauri's default is 10.13), but llama.cpp uses `std::filesystem`, which needs macOS 10.15, so `tauri.conf.json` sets `minimumSystemVersion` to `10.15`; `local-translate-build.yml` passes the same value as `MACOSX_DEPLOYMENT_TARGET`, since a plain `cargo check` uses a newer default and would not catch this. `--no-default-features` does not avoid it, since cargo still fetches the git dependency; it goes away once `llama-cpp-2` is back on crates.io. The first full `cargo test` in a new target directory takes 15–30 minutes. Real-model tests are `#[ignore]`: `TSUMUGI_TEST_MODEL=<path to plamo-3-translate-0.8b-Q4_K_M.gguf> cargo test --lib translate::llama -- --ignored --test-threads=1 --nocapture`.

Never run `./target/debug/tsumugi` or `cargo run` directly — Tauri's debug build loads the frontend from the dev server (`devUrl` = `127.0.0.1:5173`); without vite running you get a connection-refused error. Always use `cargo tauri dev`.

`cargo tauri build --debug`'s bundler step can hang 40+ minutes on some dependency-tree changes (unrelated to compilation itself, which finishes in seconds). If you just need a runnable `target/debug/tsumugi` binary (e.g. for `tauri-driver`/E2E), use `cargo build` from `src-tauri/` directly, or `cargo tauri build --debug --no-bundle`.

E2E tests (`e2e/`) launch several background processes (`Xvfb`, `dbus-run-session`, `gnome-keyring-daemon`, the `tsumugi` binary under test) that can be orphaned if a run is killed abruptly. `run-app.sh` normally reaps them itself (a detached watchdog kills every process carrying that run's `TSUMUGI_E2E_RUN_TOKEN` env var, since the WebDriver side SIGKILLs `run-app.sh` and its `trap` never runs — Issue #422), so manual cleanup is only for leftovers after an abnormal abort. Clean these up by exact PID only (`ps aux` then `kill <pid>`; `grep -az TSUMUGI_E2E_RUN_TOKEN /proc/<pid>/environ` tells E2E-spawned processes apart from your real session's) — never `pkill`/`killall` by name/pattern, since that can match unrelated real processes (e.g. a real browser) on the same machine.

On Linux/Wayland (Hyprland etc.), WebKitGTK's DMABUF renderer can request buffer formats the NVIDIA driver doesn't support and crash rendering with `Gdk Error 71 (protocol error)`. `src-tauri/src/main.rs` sets `__NV_DISABLE_EXPLICIT_SYNC=1` by default to work around this without losing HW acceleration (Tauri's recommended first fix — see https://v2.tauri.app/develop/debug/linux-graphics/); if that doesn't help, fall back to `WEBKIT_DISABLE_DMABUF_RENDERER=1` (loses HW acceleration) or `GDK_BACKEND=x11 cargo tauri dev`.

### Android
Android build support exists (`src-tauri/tauri.android.conf.json`, `src-tauri/gen/android`). CI (`android-build` job in `.github/workflows/test.yml`) only verifies it compiles and links (all four ABIs, since the local translation's llama.cpp is compiled per ABI) — no signing or artifact distribution:
```sh
cd src-tauri && cargo tauri android build --debug --target aarch64 --target armv7 --target i686 --target x86_64
```
Requires NDK r27c. NDK r27 aligns ELF LOAD segments to 4KB, which makes devices with 16KB pages show a "not 16 KB compatible" dialog on every launch (seen on a Pixel 8 Pro); `src-tauri/.cargo/config.toml` sets `-Wl,-z,max-page-size=16384` for the 64-bit targets (setting the `RUSTFLAGS` env var overrides it), and `scripts/check-android-page-size.sh <libtsumugi_lib.so> <NDK>/toolchains/llvm/prebuilt/linux-x86_64/bin/llvm-readelf` checks it (CI runs it too). The symlinks inside the NDK toolchain that `setup-ndk` extracts are relative, so they break if the extraction path changes — CI re-points them to absolute paths as a workaround (see the comment above the `Restore Android NDK symlinks` step of the `android-build` job in `test.yml`).

If the build fails during Gradle configuration with `A problem occurred configuring project ':buildSrc'` and a cause like `IllegalArgumentException: 26.0.2` (or any JDK version string), it's not an NDK issue — Gradle 8.14.3's bundled Kotlin DSL compiler can't parse newer JDK version strings when evaluating `buildSrc`'s `build.gradle.kts`. Build with an older JDK, e.g. `JAVA_HOME=/usr/lib/jvm/java-21-openjdk cargo tauri android build --debug --target aarch64`.

`MainActivity.kt` が IME(ソフトキーボード)のインセットから、キーボードが WebView 下端を覆う高さを CSS 変数 `--keyboard-inset` として WebView に設定する(マニフェストは `adjustNothing` で WebView は縮まない)。フロントはこの変数だけを参照する。`gen/android/.../generated/` は Tauri が再生成するため編集せず、`MainActivity.kt` とマニフェストだけを編集する。エミュレーターで確認するときは、FAB 等は `adb shell input tap` の本物のタップで押す(CDP の `.click()` はユーザー操作扱いにならず、キーボードが出ない/積んだ履歴が飛ばされて最初の戻るでアプリが終了する)。 回線の種類と従量制(Issue #603)も同じ `MainActivity.kt` が `ConnectivityManager.registerDefaultNetworkCallback` で監視して JNI(`nativeNetworkChanged`)で Rust に渡す(マニフェストの `ACCESS_NETWORK_STATE`、受け口は `src-tauri/src/network_status.rs`)。

## Architecture

### Rust ↔ TS boundary
`src-tauri/src/lib.rs` is the single source of truth for the command/event surface: `specta_builder()` registers every `#[tauri::command]` and every event type via `tauri-specta`. In debug builds, `run()` re-exports TS bindings to `frontend/src/bindings/tauri.gen.ts` on every launch; `cargo test`'s `generates_frontend_bindings` test also regenerates it and asserts serde's `camelCase` rename made it through and that account tokens are never exposed in generated types. When adding a command or event, register it in `specta_builder()`, not just the `tauri::Builder`.

### src-tauri/src layout
- `domain/` — normalized domain types shared across the app (Note, User, Account, Column, Reaction, Mute, ...), `specta::Type`-annotated for TS export.
- `api/` — REST client. **Hand-written, not generated** (see below) — thin typed wrappers per resource (`notes.rs`, `meta.rs`, `drive.rs`, ...) plus `normalize.rs` to convert raw responses into `domain` types. All Misskey REST calls are POST with the token embedded in the JSON body; that's centralized in `client.rs`.
- `stream/` — Streaming (WebSocket), entirely hand-implemented since it's outside Misskey's OpenAPI spec: `connection.rs` (one WS per account, ping/pong + backoff reconnect; a handshake rejected with HTTP 401 — only 401, 403 can be a transient WAF block — is `RunOutcome::Fatal`: the columns go to `Error`, the task stops retrying and exits, and `ConnectionManager::add_channel` replaces a stopped task (`cmd.is_closed()`) with a fresh one using the token it is given; the frontend calls `reconnect_column` for `error` tabs after re-auth, Issue #622. a notifications column's last seen notification ID is stashed in `ConnectionManager.stalled_notification_marks` when the task stops, and `reconnect_column` takes it to backfill missed notifications since the replacement task's first connection is not a reconnect, Issue #684), `protocol.rs` (message types), `inbox.rs` (dedupe received notes by note ID, since one shared WS can deliver the same note via multiple channel subscriptions).
- `filter/` — TQL (Tsumugi Query Language), the per-column filter DSL modeled on Krile's KQL. Designed as a two-stage pipeline: `token` → `parser` (parse + type-check) → `ast` → `eval` (in-memory, for live Streaming notes) / `sql` (SQL projection for cached/backfill queries) — see `docs/design/filter-dsl-design.md` for the grammar. Cache queries project TQL filters to SQL with `sql::build_where` (`commands/column.rs`, passed to `NoteCacheStore::search_cache`); other filter kinds use `1=1`. `filter/mod.rs` still carries `#![allow(dead_code)]` because parts of `sql` remain unconnected. `CompiledFilter` (in `filter/mod.rs`) is compiled once per column at creation time to avoid re-parsing per note. Literal `match` patterns are precompiled into `CompiledFilter::Tql { regexes }` at that time (Issue #609), so live evaluation doesn't call `Regex::new` per note; a `match` whose right-hand side is a field is still compiled per note. Always build a TQL filter with `CompiledFilter::from_expr` (never construct `CompiledFilter::Tql` directly) so the table is never skipped — `commands/column.rs` builds `from … where …` columns that way. `build_where` builds the SQL for SQLite / PostgreSQL / MySQL at once (`SqlWhere`) and each backend picks its own with `render(Dialect)`; substring matches use per-dialect functions rather than `LIKE`, and are case-sensitive. `search_cache` orders and paginates by ID (`ORDER BY n.id DESC`, `until_id` = smaller ID), the same basis as the backfill watermark and MCP cursor; the shared contract tests are in `store/search_contract.rs` (PostgreSQL/MySQL runs are `#[ignore]`).
- `store/` — persistence. Settings and drafts are plain JSON files. The note cache defaults to SQLite (`rusqlite`) but is pluggable behind the `NoteCacheBackend` trait (Issue #115 Phase 2/3) — PostgreSQL and MySQL backends are also available, switchable from the settings UI (`commands/cache_backend.rs`, `domain/cache_backend.rs`); Postgres/MySQL credentials go through the keyring like account tokens, not through settings JSON. ノートのアカウント帰属は `note_account(account_id, note_id)`(Issue #557): `note` は全アカウント共通なので、アカウント単位の絞り込み(MCP など)はこれで行う。ストリーミング受信・REST取得・ギャップ埋めの直後に `attribution::record` で記録し、`from cache` を含むカラムの REST取得・ギャップ埋めでは記録しない(グローバルなキャッシュ由来のノートが混ざるため)。記録が欠けると「見えない」側に倒れる設計で、既存データは起動時とバックエンド切り替え後に `attribution::backfill_all` が `column_note` から埋め直す。Cache schema migrations must be idempotent with no marker table: use "the legacy column still exists" as the not-yet-migrated marker, copy with `ON CONFLICT DO NOTHING` (MySQL: `INSERT IGNORE`), then `DROP COLUMN` (MySQL DDL auto-commits, so copy+drop is never atomic there). Never guard an add-columns migration on a column you later drop (SQLite `migrate_cache` guards on `emojis`, not `instance_name`). In SQLite, wrap each guarded step in one `unchecked_transaction` (DDL is transactional there): when the guard is the added column itself, an interruption between `ADD COLUMN` and the backfill/next `ALTER` otherwise leaves a column that makes the next start treat the step as done (`created_at = 0` persisted) or fail with `duplicate column name` (Issue #618). 設定のエクスポート/インポート(Issue #544)の純粋ロジックは `store/settings_transfer.rs`(`parse_export` / `build_export` / `plan_import`)、I/Oとアプリ状態の更新は `commands/settings_transfer.rs`。インポートしたトークンなしアカウントのホストは `fetch_allowlist` に入れない(`AppState::refresh_fetch_allowlist` はトークンを持つアカウントだけを見る)。 `SettingsStore` の更新メソッドは、メモリを直接書き換えず `update` / `commit` を通す(保存に成功してから差し替える。失敗したら何も変えない。Issue #696)。足したら、テストの `update_ops` にも足す。`DraftStore` は手動下書きだけ同じ順序で、自動下書き(`save_auto` / `clear_auto`)は保存に失敗してもメモリを正とする(巻き戻すと、古い本文や投稿済みの本文が復元される)。
- `session/` — account/token management; tokens go through the OS secret store, never through the frontend. Uses `keyring-core` + a platform-specific store crate directly (`apple-native-keyring-store` / `windows-native-keyring-store` / `zbus-secret-service-keyring-store` / `android-native-keyring-store`) — deliberately not the `keyring` crate's v1-compatible wrapper, since that has no Android support (see `session/secrets.rs`).
- `scheduler.rs` — client-side scheduled posts (Issue #60 B, for servers without server-side scheduling): a resident task posts due entries from `store/scheduled_post.rs` via `create_note`, only while the app is running. Entries older than `MISSED_GRACE_SEC` are marked `Expired` and never auto-posted; a request that may have reached the server (timeout etc.) is never retried, to avoid duplicate posts. Save order in `store/scheduled_post.rs` (Issue #620): a transition **before** sending (`begin_post`) saves first and rolls memory back if the save fails (so it neither sends nor sticks at `Posting`); recording a result **after** sending (`finish_posted` / `finish_failed` / `finish_retry`) keeps memory as the truth even if the save fails (rolling back would invite a resend), sets `dirty`, and the scheduler loop calls `flush()` each cycle until the disk catches up. User operations (`add` / `cancel` / `remove_account`) go through `save_or_restore`: a failed save restores memory and returns `Err`, so the reported failure matches the state (Issue #682). `TSUMUGI_DEBUG_SERVER_VERSION` (debug builds only) overrides the detected server version so the E2E can exercise this path (see `e2e/README.md`).
- `translate/` — ローカル翻訳(PLaMo 3 Translate、Issue #603、設計は `docs/superpowers/specs/2026-11-14-local-translate-plamo-design.md`)。`translate_note` が `UiPrefs.translate_engine`(`"server"` | `"local"`、未知の値は `server`)で、Misskey サーバーの `notes/translate` とローカル翻訳を振り分ける。`prompt.rs`(PFML3 プロンプト。**PLaMo 3 のトークナイザは `parse_special = false` でも本文中の `<|plamo:tag|>` などをスペシャルトークンへ変換する**ので、本文は `sanitize_text` で `<|` の間にゼロ幅スペースを挟んでからトークン化する。固定部分だけがスペシャルトークンになる)、`lang.rs`(設定の言語コード→PLaMo の 53 言語。`zh`→`zh-hans`、地域付きは地域を除く、`pt` - `net_guard.rs` — destination checks for the commands that fetch an arbitrary WebView-supplied URL (`save_url_to_file` / `fetch_url_bytes`, Issue #377). `AppState.fetch_http` carries a DNS resolver and redirect policy that reject loopback/private/link-local targets (connections only ever go to validated IPs, so DNS rebinding doesn't work); the hosts of logged-in accounts are exempt via `AppState.fetch_allowlist` — call `refresh_fetch_allowlist()` whenever accounts are added or removed. The summaly host never enters `fetch_allowlist`, so it can't weaken the media-fetch guard; `refresh_fetch_allowlist()` updates both lists. `AppState.http` (API traffic) is outside this guard. HTTP client timeouts (Issue #606): `AppState.http` is built by `api::client::build_http_client` (connect 20s + total 60s (generous for mobile links); `api/drive.rs` raises uploads to 600s per request), while `build_fetch_client` (`fetch_http` / `preview_http` / the model download) has connect 20s + `read_timeout` 60s and deliberately no total cap, so large downloads survive as long as bytes keep flowing. A new `reqwest::Client` must set timeouts too — reqwest's default is unlimited.
- `nav_guard.rs` — **Android only** (the plugin is registered under `#[cfg(target_os = "android")]` in `run()`; Issue #660): an `on_navigation` hook that keeps the main WebView from navigating to a non-app origin. Android's WebView has no `target="_blank"` new-window support, so `<a target="_blank">` / `window.open()` become a main-frame navigation, and the external page loads with Tauri's IPC injected (ACL-denied, but still). `decide()` is pure and unit-tested: `Allow` (`tauri.localhost`, `about:blank`, the `devUrl` under `cargo tauri dev`) / `OpenExternal` (other `http(s)` / `mailto` / `tel`) / `Block` (anything else). **The hook runs on the UI thread: never call `opener().open_url()` (or any `run_mobile_plugin`, which waits synchronously for Kotlin's reply) inside it — spawn a thread** (a direct call deadlocked the UI thread and the app was ANR-killed, seen on a real device; unit tests can't catch it). It is deliberately not registered on desktop: wry's hook has no main-frame/subframe distinction and Linux (WebKitGTK) / macOS (WKWebView) very likely call it for subframes too (unmeasured), so denying non-app origins there would break the `UrlPreviewCard` player `<iframe>`, and desktop has no in-place navigation problem to begin with. On Android it was measured to fire for main-frame navigations (`location.assign`, `window.open`) and not for `<iframe>` loads or `src` changes. `lib/externalLinks.ts` (Issue #657) normally opens links first; this is the backstop.

- `state.rs` — `AppState`, the single Tauri-managed state struct threading together accounts, secrets, connections, mute config, and settings; commands pull what they need from `State<AppState>`.
- `debug_bridge.rs` — debug-build-only (`#[cfg(all(debug_assertions, desktop))]`), not registered in `specta_builder()`. ### frontend/src layout
- `ui/` — Svelte components (columns, compose bar, settings, account management).
- `render/` — note content rendering (MFM, emoji, media grid).
- `input/` — input widgets (e.g. reaction picker).
- `lib/` — cross-cutting utilities (IPC wrapper, theme, keymap, time formatting, MFM/nyaize helpers).
- `bindings/tauri.gen.ts` — **generated**, do not hand-edit; regenerate via `cargo test` or `cargo tauri dev`.

`frontend/index.html` sets `<meta name="referrer" content="no-referrer">` so external images (avatars, emoji, Instance Ticker icons) aren't 403'd by Cloudflare-style hotlink rules (Issue #411). An embed that needs a Referer (e.g. the `UrlPreviewCard` player iframe) must set its own `referrerpolicy`.

WebKitGTK's native `<input type="datetime-local">` / `date` / `time` can't be used to pick a time (Issue #430, #60): use `ui/DateTimeInput.svelte` (or the `datePicker` action in `lib/flatpickrDatePicker.ts` when you need a `Date`) instead of a native date/time input — see `docs/design/style-guide.md` §12.

Under `cargo tauri dev` (page origin `http://127.0.0.1:5173`), WebKitGTK (seen on 2.54.1) can't load `asset://` from `<img>` / CSS `background-image` (no-cors loads fail; `fetch()` and `crossorigin="anonymous"` work). The embedded-frontend build (`tauri://localhost`) loads it fine, so this shows up only in dev on Linux (Android/Windows use http-style origins and are untested). Don't pass `convertFileSrc(...)` straight to `src` / `url()`: go through `lib/assetBlob.ts`'s `loadAssetBlobUrl` and revoke the blob URL yourself (the background image/video and the settings preview do this).

WebKitGTK layout quirk (Issue #166): when an `overflow:auto` box that needs a horizontal scrollbar (e.g. the code-block `pre`) is first laid out lazily, the scrollbar's height isn't propagated to its parent, so the next sibling (the note footer) stays overlapped by the scrollbar. Forcing a synchronous layout right after DOM insertion fixes it — `CodeBlock.svelte` reads `offsetHeight` for this. When investigating similar bugs, don't read geometry (`getBoundingClientRect` etc.) right after inserting a node: that read itself triggers the heal and masks the bug.

External links (`<a href="https://…">`, `target="_blank"` or not) are opened by `lib/externalLinks.ts` (`installExternalLinkHandler()`, called from `main.ts`), which listens for `click` on `window` in the **capture** phase (Issue #657). Don't rely on `tauri-plugin-opener`'s own `window` bubble-phase script alone: it never sees clicks under an ancestor that calls `stopPropagation()` (e.g. the `Modal` dialog body — the profile bio), and then Android's WebView navigates the main frame to the external site itself (the page loads with Tauri's IPC injected, and going back reloads the app and loses its state). New links need no special handling, but an event handler that must run before it has to be registered on `window` in the capture phase before `installExternalLinkHandler()`, since it skips already-`defaultPrevented` clicks.

### progenitor is not used for REST codegen
Misskey's OpenAPI spec (served at `/api.json` — `/api-doc.json` returns the SPA's HTML; snapshotted from upstream `misskey-dev/misskey` at `src-tauri/openapi/misskey-api-doc.json`, version in `VERSION.txt`) is **3.1.0**. The snapshot is reference-only (nothing reads it at build/run time) and ages quickly; for what a server supports, check a live instance's `/api.json`. `progenitor` depends on the `openapiv3` crate, which only supports OpenAPI 3.0.x, so it fails to parse Misskey's spec (nullable fields expressed as `type: ["string", "null"]`). This was tried and rejected during Phase 1 — see `docs/design/misskey-multicolumn-client-design.md` §6.1. The REST client is fully hand-written instead (`src-tauri/src/api/`); don't reintroduce a progenitor build step without re-validating against the current spec.

### specta/tauri-specta versions are pinned
`specta`, `specta-typescript`, and `tauri-specta` are pinned to exact versions (`=2.0.0-rc.25` / `=0.0.12`) in `Cargo.toml`. Don't loosen these without checking that TS binding generation still works — see `docs/design/phase0-scaffold.md` for context.

## Development workflow

- Never commit directly to `main`. Create a feature branch before touching any file (branch first, edit second — never the other way around).
- Fixes tied to a GitHub issue go through a PR, not a direct merge. Put `Fixes #N` or `Closes #N` in the PR body — referencing the issue number alone does not auto-close it on merge.
- After pushing, don't poll CI with Monitor/wait loops; the user checks CI results themselves.
- Commit messages: subject line only, no body/bullet points (the Co-Authored-By trailer is appended separately).
- `Agent` calls with `isolation: "worktree"` branch off `main`, not off the current feature branch — don't use that isolation mode for subtasks that depend on in-progress feature-branch changes.
- `.github/pull_request_template.md` only gets applied on the Web UI, or via `gh pr create` when it opens an interactive editor (no `--body`/`--body-file`/`--fill`). Passing `--body`/`--fill` to `gh pr create` skips the template, so PR bodies written that way need to follow its structure manually.

## PR merging

`main` is a protected branch (no direct push, no force push — even for cleanup). When merging a PR, default to a normal merge commit (`gh pr merge --merge`), not squash, unless explicitly told otherwise. Squashing and then wanting a plain merge commit instead requires rewriting already-pushed history, which branch protection blocks outright — there's no clean way to fix it after the fact.

## Release process

1. `git checkout main && git pull origin main` — release branches off up-to-date main.
2. Decide the next version (semver: bump minor for feature additions since the last tag, patch for fix-only ranges). Check what's shipped since the last tag with `git log <last-tag>..main --oneline`.
3. `scripts/release.sh X.Y.Z` — creates `release/vX.Y.Z`, bumps the version in `frontend/package.json` / `src-tauri/Cargo.toml` / `src-tauri/tauri.conf.json` / `src-tauri/Cargo.lock` and the download links in `README.md`, generates `CHANGELOG.md` via `git-cliff`, and commits as `chore(release): vX.Y.Z`.
4. `git push -u origin release/vX.Y.Z` then `gh pr create` — the release branch goes through a PR like any other change, not a direct local merge to main.
5. Once CI passes, `gh pr merge <N> --merge` (normal merge commit, not squash — see PR merging above).
6. `git checkout main && git pull origin main`, then tag the merge commit and push it: `git tag -a vX.Y.Z -m "vX.Y.Z" && git push origin vX.Y.Z`.
7. Pushing the `vX.Y.Z` tag triggers `.github/workflows/release.yml`, which builds installers for Linux/macOS/Windows plus signed Android APKs and publishes them as a **draft** GitHub Release (`releaseDraft: true`). Actually publishing the release (editing notes, unmarking as draft) is a manual step on GitHub — not automated.
