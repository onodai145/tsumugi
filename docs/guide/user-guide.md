# tsumugi ユーザーガイド

## tsumugiとは

tsumugiは、Misskey向けのマルチカラムデスクトップクライアントです。Krile風のUXで、複数のタイムライン・リスト・アンテナ・通知などを横に並べて同時に見られます。1つの「カラム」の中に複数の「タブ」を持たせることもでき、タブ単位でTQL（後述）によるフィルタも設定できます。

## インストール・起動

OSごとのインストーラ・実行ファイルは [README のダウンロードセクション](../../README.md#ダウンロード) から入手できます。ソースからビルドする場合の手順・必要環境も [README](../../README.md) を参照してください。

> **Linux/Wayland環境の注意:** WebKitGTKの描画で問題が出る場合は[トラブルシューティング](#トラブルシューティング)を参照してください。

## 基本操作

### アカウントの追加

設定画面の「アカウント」セクションから「＋ アカウントを追加」でMisskeyアカウントを追加します。複数アカウントを同時にログインでき、投稿バーやカラムごとにどのアカウントを使うか選べます。

### カラムとタブ

- **カラム**: 画面に横に並ぶ視覚的な列です。幅を持ち、並び替えられます。
- **タブ**: 1つのカラムの中に複数持てる、実際のタイムライン(受信ソース＋フィルタ)です。カラムの上部にタブバーとして並びます。

### カラムの追加とソース種別

タブバー右端の「⋯」メニューから「タブを追加」を選ぶとカラム（またはタブ）を追加できます。追加モーダルには「簡単」モードと「エキスパート(TQL)」モードがあります。

「簡単」モードで選べるソース種別:

| 種別 | 内容 |
|---|---|
| Home | ホームタイムライン（フォロー中のユーザーの投稿） |
| Local | ローカルタイムライン |
| Hybrid | ソーシャル（ホーム＋ローカル）タイムライン |
| Global | グローバルタイムライン |
| List | 指定したリストのタイムライン |
| Antenna | 指定したアンテナのノート |
| Channel | フォロー中チャンネルのタイムライン |
| User | 指定ユーザー（`@user@host`）の投稿一覧。ライブ更新なし |
| Tag | 指定ハッシュタグの検索結果。ライブ更新なし |
| Search | キーワード検索結果。ライブ更新なし |
| Notifications | 通知 |

List/Antenna/Channelは、Misskey側に作成済みのものが一覧に表示され、そこから選びます（無い場合はその旨のメッセージが表示されます）。

各カラム/タブには任意で名前を付けられます（空欄なら種別から自動生成されます）。

### タブのフィルタ（TQL）

通知タブ以外では、TQL（Tsumugi Query Language）によるフィルタを設定できます。空欄なら全件表示です。例:

- `has_files` — 添付ファイルがあるノートのみ
- `!bot && local` — bot以外のローカルユーザーの投稿のみ
- `reactions >= 10` — リアクション合計10以上
- `text -> "rust"` — 本文に「rust」を含む

「エキスパート(TQL)」モードでは `from home, list("id") where has_files && !cw` のように、複数ソースを合成した完全なクエリを直接書けます。使えるソース: `home` / `local` / `hybrid` / `global` / `list("id")` / `antenna("id")` / `channel("id")` / `user("@acct")` / `tag("name")` / `search("q")` / `cache`（ローカルキャッシュ検索）。list/antenna/channelは生のIDを指定する必要があります。

Local/Hybridカラムは返信も含めて全件表示します。従来のように返信を非表示にしたい場合は、TQLで `where !reply`（返信をすべて除外）や `where !reply || reply_to_me`（自分宛の返信は残しつつ、他人宛の返信だけ除外）のように指定してください。`reply_to_me` は「自分宛の返信」に絞り込む述語なので、単体で指定すると返信でない通常の投稿まで消えてしまう点に注意してください。

TQLの文法の詳細は設計書 [`docs/design/filter-dsl-design.md`](../design/filter-dsl-design.md) を参照してください。

### このタブの通知

search/user/tag以外のソースでは、タブごとに「デスクトップ通知」「通知音」のON/OFFを設定できます。通知音はプリセットの他、任意の音声ファイルを選んで試聴もできます（未指定なら設定画面のグローバル選択を継承します）。

#### MML で通知音を作る

通知音の種類で「MML（打ち込み）」を選ぶと、着メロのように音符をテキストで打ち込んで通知音にできます。音符・休符・コマンド・音色・数字・コメントは色分けされます。入力欄の下に再生時間が出れば構文は正しく、「試聴」で鳴らせます。書き方が誤っているときは、原因の文字に波線が引かれ、「N 文字目」を押すとその位置にカーソルが移ります。直すまで保存できません。その下に、文字数・音の数・トラック数・再生時間が上限と並んで出ます(上限の 9 割を超えると太字と色で知らせ、超えると赤くなります)。音の数と再生時間は、構文が通っているときだけ出ます。「サンプル」のボタン(ジングル・2 トラック・アルペジオ)で、短い例を入れられます。入力があるときは、置き換えてよいかを確認します。入力欄の下の「音色」のボタンを押すと、カーソル位置に `@名前` が入ります(書き方の説明は「記法」を開くと読めます)。スマホ向けの画面(モバイル UI)では、入力欄のすぐ下に入力補助のキーが出ます。音符(`c d e f g a b`、休符 `r`)、`#` `-` `.` `&` `^`、オクターブ `<` `>`、長さ(`1 2 4 8 16 32`)、音色パラメーター `y` `m` `k` `p` `,`、`[` `]` `:` `{` `}` `'` `$` `;` を押すと、カーソル位置にその文字がそのまま入ります(空白は入らないので、`c` `8` と押せば `c8` になります)。キーを押してもソフトキーボードは閉じません。PC 向けの画面では出ません。

例: `t120 o5 l8 cdefgab>c`

| 書き方 | 意味 |
|---|---|
| `c d e f g a b` | 音符。`#` または `+` で半音上げ、`-` で半音下げ |
| 音符の後ろの `1 2 4 8 16 32 64` | 長さ（4 が四分音符）。`.` を付けると付点（最大 2 個） |
| `r` | 休符（長さは音符と同じ書き方） |
| `&` | タイ。`c4&c8` のように同じ高さの音符をつなぐ |
| `^` | タイ(長さを足す)。`c4^8` のように、直前の音符を後ろの長さだけ伸ばす（長さを省くと `l` の値）。`&` と違い、次の音符を書かずに伸ばせる。休符の後ろには使えない |
| `v+2`、`v-2` | 音量を相対で上げ下げ（1〜15、数字を省くと 1）。結果が 0〜15 を出るとエラー |
| `q80` | 音を鳴らす長さの割合（1〜100、既定 100）。短くするとスタッカートになる。次の音の始まりは変わらない |
| `{cde}4` | 連符。中の音符・休符の長さを合計して、後ろの長さ（省くと `{` の時点の `l`）1 つ分に収める。`{c4 d8}4` のように長さを書いたときは、その比で割る。入れ子は不可 |
| `'ceg'4.` | 和音。単引用符で囲んだ音を同時に鳴らす。長さと付点は閉じの `'` の後ろに 1 つ（和音全体の長さ。省略すると `l` の値）。中に書けるのは音符（`#` `+` `-` つき）と `<` `>` だけ（`'c>c'` はオクターブ違いの和音で、`<` `>` は和音の間だけ効き、後ろは元のオクターブに戻る）。各音の音量は `v` の音量を音数で割る（`'ceg'` の各音は 1/3。和音は単音より小さく聞こえる）。`^` は和音の全部の音を延ばす（`'ceg'4^4`）。`&` とは組み合わせられない。音の数は、和音の各音を 1 つずつ数える |
| `$riff={c d e f}`、`$riff` | マクロ(同じフレーズに名前を付けて、文字数を節約する)。`$名前={…}` で定義し、`$名前` で展開する(文字の置き換え)。定義はどこに書いてもよく、全トラックで使える(使う前に書かなくてもよい)。名前は英小文字・数字・`_` で、`$` の直後に途切れなく続く並びが名前になる(大文字は小文字として扱う)。**名前の直後に英数字か `_` が続くときは、空白かコメントで区切る**(`$riff 4` と書く。`$riff4` は名前 `riff4` になる)。`$a` と `$ab` は別のマクロ。本体にはその場に置いて意味が通る MML を書ける(本体の中の `{ }` は連符と同じく対で数える)。`;`(トラックの区切り)と定義は書けない。マクロの中から別のマクロを使えるが、再帰はエラー。展開後の文字数は 100,000 文字まで。本体の誤りは、定義の中の文字を指す。定義だけの区間(`$a={c} ; d` の `;` の前)は、トラックに数えない |
| `// …`、`/* … */` | コメント。`//` は行末まで、`/* */` は範囲（入れ子不可、閉じ忘れはエラー）。`;` を含んでもトラックは分かれない。文字数（5000）には含む |
| `o4`、`>`、`<` | オクターブ指定（1〜8、既定 4）、1 つ上げる、1 つ下げる |
| `l8` | 以降の既定の長さ（既定は 4） |
| `t120` | テンポ（32〜255、既定 120） |
| `t=140` | 全トラックの初期テンポ（32〜255）。トラックの最初の音符・休符・和音より前に、1 回だけ書ける（どのトラックでもよい。繰り返し・連符の中は不可）。トラックごとの `t120` は、そのトラックだけを上書きする。`t=140` だけのトラックもトラックに数えられる（上限の 4 に含まれ、音量が下がる）ので、普通は最初のトラックの頭に書く（`t=140 c d e ; o3 c g`） |
| `v10` | 音量（0〜15、既定 10） |
| `@3`、`@bell` | 音色の指定（番号か名前。下の表を参照）。何も書かなければ `@0`（`fm`）。以降の音がその音色になる |
| `[cde]3` | 繰り返し（2〜99 回、入れ子可）。`[c:d]3` のように `:` を入れると、最後の回だけ `:` の後ろを飛ばす（`c d c d c`）。展開後の命令が 50 万個を超えるとエラー |
| `;` | トラックの区切り（最大 4 つ。和音になります） |

大文字小文字は区別せず、空白と改行は無視します(コメントも読み飛ばします)。全体で 5000 文字、再生時間は 90 秒、音は 3000 個までです。通知音にすると通知のたびに最長 90 秒鳴り続けるので、通知音には短い曲をおすすめします。音符が多い曲や長い曲は、最初の試聴や保存したあとの準備(音の生成)に時間がかかります。音が多く長いほど遅く、上限いっぱいのものは数分かかることがあります(生成は裏で続きます)。生成中は「試聴」のボタンが「生成中… N 秒」に変わり、隣に「待たない」が出ます。「待たない」を押すか、入力を編集すると、その生成の結果は捨てて待つのをやめます(鳴りません)。生成そのものは止められず裏で終わりまで続きますが、できた音は覚えているので、同じ MML をもう一度試聴すれば、すぐ鳴ります。デスクトップ版 Linux での描画の測定では、生成の最中に画面が止まったのは長くても 2 秒弱でした(Android では測っていません)。重い MML を保存すると、アプリの起動時にも保存済みの通知音の生成が裏で走るため、上限いっぱいの MML だと起動のたびに数分間、裏で生成が続くことがあります。目安として、210 音・85.7 秒の曲で約 4 秒でした(上と同じ測定での値で、環境によって変わります)。トラックごとにテンポ・オクターブ・長さ・音量・音色は独立していて、テンポを揃えたいときは、最初のトラックの頭に `t=140` を書くか、各トラックに `t` を書いてください。

音色は次の 15 種類です。`@3c` のように番号の直後に音符を続けても、`@bell c` のように名前で書いても使えます。トラックの途中で何度でも切り替えられます。

| 番号 | 名前 | 音の作り方 |
|---|---|---|
| 0 | `fm` | FM 音源（既定。音色指定がない MML はこの音で鳴ります） |
| 1〜5 | `square` `pulse` `triangle` `saw` `sine` | 矩形波・パルス波(幅 25%)・三角波・ノコギリ波・サイン波 |
| 6 | `organ` | 倍音を重ねたオルガン風 |
| 7 | `epiano` | FM 音源の電子ピアノ風 |
| 8 | `bell` | FM 音源の鐘風 |
| 9 | `am` | AM 音源 |
| 10 | `lead` | ビブラートつきのリード |
| 11 | `bass` | ローパスをかけたベース。低い音向きで、C6 より高い音は小さくなります |
| 12 | `drum` | ドラム風（音程は下がっていきます） |
| 13 | `noise` | ノイズ（音程はなく、ハイハットやスネアのような音） |
| 14 | `drumkit` | ドラム(音の高さでキック・スネア・ハイハットなどを打ち分けます。下の表を参照) |

**`@drumkit` の割り当て**: General MIDI(GM)のドラムと同じ高さで鳴ります(`o2 c` が 36 番)。書いた音の長さ(と `q`)は無視して、楽器ごとの決まった長さで鳴ります。音量 `v` は効きます。割り当てのない高さの音は鳴りません(エラーにもなりません)。`'cf+'` のように和音で書くと、キックとハイハットが同時に鳴ります。

| 楽器 | 書き方 |
|---|---|
| キック | `o2 c`(36)、`o1 b`(35) |
| サイドスティック | `o2 c+`(37) |
| スネア | `o2 d`(38)、`o2 e`(40) |
| ハンドクラップ | `o2 d+`(39) |
| タム(低い順) | `o2 f`(41)、`o2 g`(43)、`o2 a`(45)、`o2 b`(47)、`o3 c`(48)、`o3 d`(50) |
| クローズドハイハット | `o2 f+`(42)、`o2 g+`(44) |
| オープンハイハット | `o2 a+`(46) |
| クラッシュシンバル | `o3 c+`(49)、`o3 a`(57) |
| ライドシンバル | `o3 d+`(51)、`o3 b`(59) |
| ライドベル | `o3 f`(53) |
| カウベル | `o3 g+`(56) |

例: `@drumkit t120 o2 [c8 f+8 d8 f+8]4`(キック・ハイハット・スネア・ハイハットの 4 拍)。

**音色のパラメーター**: `y` `m` `k` で、音の立ち上がり・余韻やビブラート、音程のずれを、トラックごとに変えられます。書いた所から後の音に効き(次の音から)、`t` `v` `q` と同じように、トラックごとに独立します。ループやマクロの中にも書けます。和音の中には書けません(和音の前に書きます)。`drum` `noise` `drumkit` には効きません。

| 書き方 | 意味 |
|---|---|
| `y10,200,60,300` | エンベロープ。アタック(ミリ秒、0〜2000)、ディケイ(ミリ秒、0〜2000)、サステイン(0〜100 %)、リリース(ミリ秒、0〜600)。4 つすべて書きます。`y0` で、音色の既定に戻します |
| `m5,30` | ビブラート。速さ(Hz、1〜20)、深さ(1〜100。音程の揺れの片側の幅で、おおよそのセントです。`m5,30` は約 ±30 セント。速さが遅いと頭打ちになり、1 Hz は約 ±27 セントまで、4 Hz 以上なら 100 まで使えます)。`m0` で解除します。`lead` が持つ組み込みのビブラートは、`m` と関係なく残ります |
| `k+12`、`k-12` | デチューン(音程のずれ、セント。−100〜100)。`k0` で解除します |

**ポルタメント**: `p80` と書くと、そこから後は、休符も和音もはさまずに続く音が、前の音の高さから滑って入ります(`80` は滑る時間のミリ秒で、1〜1000。`p0` で止めます)。`y` `m` `k` と同じトラックの状態で、ループやマクロの中にも書けます。和音の中には書けません。

例: `@lead p120 o4 c4 e4 g4 p0 c4`(`e` は `c` から、`g` は `e` から滑って入り、最後の `c` は滑りません)。

- 滑る音も、頭から立ち上がります(1 つの音を鳴らし続けて高さだけ変える、本物のレガートとは違います)。
- 休符の後の音、和音と和音の直後の音、前と同じ高さの音は、滑りません。`drum` `noise` `drumkit` にも効きません。
- 滑る時間が音の長さより長いときは、音の長さに縮まります(音が消えるまでに、目的の高さに着きます)。
- `q` でゲートを短くしても、休符を書いていなければ滑ります。`k` のデチューンとは、同時に使えます。

例: `@lead y5,100,70,400 m5,40 o4 [c d e f]2`。エンベロープとビブラートの組(値の組み合わせ)が多い MML(音ごとに値を変えるなど)は、組ごとに音源を作るので、描画に時間がかかります(目安は、組が 20 通りで数秒、数百通りだと数分)。デチューンは、組に数えません。`@` で音色を切り替えても、パラメーターは保たれます。`m` の深さは、おおよその値です。`y` のサステインを大きくしたときの音の大きさも含めて、実際に聴いて調整してください。

保存した MML は、設定→通知のグローバル設定と、タブごとの通知音の両方で使えます。何らかの理由で音を作れなかったときは、通知を止めずにビープ音で代わりに鳴らします。

## 検索

画面下部のメニュー（ハンバーガーアイコン。「＋カラム」「設定」と並びます）から「検索」を選ぶと、検索モーダルが開きます。カラムを追加せず、その場限りで検索したいときに使います。「検索対象」で次の2つを切り替えられます。

- **キャッシュ**: ローカルにキャッシュ済みのノートを検索します。
- **サーバー**: 選択中のアカウントのMisskeyサーバーの検索機能（`notes/search`）に問い合わせます。キャッシュに無いノートも探せます。

- **アカウント**: キャッシュ検索では、検索結果のノートに対して返信・Renote・リアクション等の操作を行うアカウントを選びます（検索条件そのものには影響しません。キャッシュは全アカウント共通です）。サーバー検索では、そのアカウントのサーバーに検索を問い合わせます。
- **簡単モード**: 既定ではキーワード欄のみ表示されます。「詳細条件を指定」を押すと、ユーザー（`@user@host`形式。自インスタンスのユーザーは`@user`のみ）・インスタンス（空欄で全インスタンスが対象）・日時範囲（開始/終了）の各条件を追加できます。
- **エキスパート(TQL)モード**（キャッシュ検索のみ）: `cache`ソースのwhere句を直接書けます（例: `has_files && user.acct == "@alice@misskey.example"`）。
- **サーバー検索の条件**: キーワードは必須です。インスタンス欄に自分のサーバーを指定したいときは、ホスト名か `.` を入力します。サーバー検索ではエキスパート(TQL)モードは使えません。
- **日時範囲（サーバー検索）**: Misskey 2025.7.0以降のサーバーでのみ指定できます。バージョンを取得できないサーバーや古いサーバーでは日時欄は表示されません。Misskeyのフォーク（Sharkey等）はバージョン番号が本家と対応しない場合があり、番号が新しくても日時の指定が効かないことがあります。
- キャッシュ検索の対象は**この端末にローカルキャッシュ済みのノートのみ**です。まだ一度も受信・取得していないノートはヒットしません。サーバー検索はサーバー側の検索機能に依存するため、サーバーが検索を無効にしている場合などは結果が返りません。
- 結果はスクロールで追加読み込みされ、通常のカラムと同様に各ノートへ操作できます。

## タブ・カラムの並び替え/幅調整

- **カラムの並び替え**: タブバー左端のグリップアイコンをドラッグ&ドロップで並び替えます。
- **カラム設定を開く**: タブバー右端の「⋯」メニューから「カラム設定」を選ぶと、カラム設定（幅・自動調整など）が開きます。
- **タブの並び替え・移動**: 各タブ自体もドラッグでき、同じカラム内はもちろん別カラムへも移動できます。
- **タブの編集**: タブ名をダブルクリックすると、そのタブの設定（種別・フィルタ・通知）を編集できます。タブ名だけを変更した場合は、表示中のノートはそのまま残ります（種別やフィルタを変更したときは、新しい条件でノートを取得し直します）。
- **タブを閉じる**: アクティブなタブの右側に出る×ボタンで閉じます。
- **カラムを縦に分割**: タブバー右端の「⋯」メニューから「下に分割」を選ぶと、カラムを縦方向に分割し、新しいペインを作れます。
- **カラム幅の調整**: カラム右端の境界をドラッグして220〜720pxの範囲で調整します。「自動」設定のカラムはウィンドウ幅に応じて自動調整されるため、この操作はできません。
- 各タブ名の左のドットの色が接続状態を表します（接続済み/接続中・再接続中/エラー）。
- **モバイル版でのスワイプ操作**: ノート・通知一覧を左右にスワイプすると、そのカラム内のタブを切り替えられます。先頭/末尾のタブでさらにスワイプを続けると、隣のカラムへ移動します。
- **モバイル版でのタブ/カラム並び替え**: タブ・カラムグリップのどちらも指で長押しするとドラッグモードに入ります。タブは指の動きに追従して並び替えられます。カラムは画面上部に出る「◀ 前へ / 次へ ▶」のヒントで隣のカラムと入れ替えます（1回のドラッグで1つ隣まで）。「⋯」メニューの「左に移動」「右に移動」からも同じ操作ができます。
- **モバイル版での画面表示**: 設定・検索・プロフィール・カラム追加などは全画面で開き、左上の「←」または端末の戻る操作で閉じます。エラー表示や確認ダイアログは、従来どおり小さなダイアログで表示されます。

## 投稿

投稿バーは画面上部にあります（モバイルUIでは非表示になり、代わりに新規投稿ボタンから全画面の投稿画面で投稿します）。

- **モバイル版の投稿画面**: 入力欄が画面いっぱいに広がり、公開範囲・画像・CW・投稿などのボタンがキーボードのすぐ上に並びます。

- **本文**: `Ctrl+Enter`（macOSは`⌘+Enter`）で投稿できます。`:絵文字名:`・`@メンション`・`#タグ`・MFM構文の入力補完に対応し、クリップボードから画像を直接貼り付けることもできます。ファイルマネージャでコピーしたファイル(画像・動画など)も `Ctrl+V` で添付できます(Linux の Wayland ではコンポジタが `ext-data-control` または `wlr-data-control` に対応している必要があります。フォルダは添付できません)。
- **公開範囲**: 「公開」「ホーム」「フォロワー」「ダイレクト」から選べます。
- **CW（内容警告）**: 「CW」ボタンで内容警告欄をON/OFFできます。
- **投票**: 「投票」ボタンでON/OFFできます。選択肢は最大10個まで追加でき、複数選択可否や、無期限/日時指定/期間指定の締切を設定できます。
- **添付ファイル**: 画像アイコンから「ローカルから選択」（OSのファイルピッカー）または「ドライブから選択」（Misskeyドライブ）で添付できます。
- **Android からのシェア**（Android版のみ）: 他のアプリからテキストや画像、動画をシェア（共有）すると、tsumugi が選択肢に表示されます。シェアを選ぶと、共有されたコンテンツが投稿バーのコンポーズ欄に自動的に入力されます。tsumugi が既に起動している場合はそのまま表示され、起動していない場合は自動的に起動します。複数の画像・動画をシェアすることもできます。
- **連合なし**: チェックを入れると他インスタンスへ配送されないローカル限定投稿になります。
- **返信・引用**: ノートの返信/引用ボタンから開始すると、投稿バー上部にその対象が表示され、×でキャンセルできます。
- **予約投稿**: 投稿バーのカレンダー時計アイコンから、投稿する日時を指定して予約できます。日時を入れると投稿ボタンが「予約」に変わります。投票の締切を「期間指定」にした場合は、予約日時からの期間になります。
  - **サーバー側の予約**: サーバーが予約に対応している場合(Misskey 2025.10.0 以降)は、予約はサーバー側に保存されるため、tsumugi を閉じていても指定した日時に投稿されます。予約時刻になっても投稿に失敗した場合(返信先が削除された等)は、一覧に「投稿に失敗」と表示されて残ります。
  - **tsumugi が投稿する予約(ローカル予約)**: 対応していないサーバーでは、tsumugi が予約を保持して自分で投稿するため、**tsumugi を起動している間だけ**投稿されます(予約時にその旨が表示されます。Android では、バックグラウンドで停止された場合も同様に投稿されないことがあります)。起動していない間に予約時刻を過ぎた予約は、予約時刻から 5 分以内に起動すれば投稿され、5 分を超えると自動では投稿されず、予約一覧に「期限切れ」として残ります。
  - **予約一覧**: 「予約一覧」から、予約済みの投稿の確認・取り消し・「作成欄に戻す」(内容と、未来の予約日時を投稿バーに読み込んで予約を取り消す。期限切れ・投稿に失敗した過去の予約は日時を戻さない)ができます。ローカル予約が期限切れ・失敗した場合は「今すぐ投稿」もできます。

## リアクション・Renote・引用・返信、通知アクション

各ノートの下部に以下のアクションボタンが並びます（自分のアカウントのタブでのみ表示）。

- **返信**: 投稿バーに返信モードで反映されます。
- **Renote**: クリックで即座にRenoteします（連打防止のため3秒間のクールダウンがあります）。ホバーで誰がRenoteしたか確認できます。フォロワー限定投稿は自分の投稿のときのみ、ダイレクト投稿はRenoteボタン自体が表示されません。
- **引用**: 投稿バーに引用モードで反映されます。
- **リアクション**: クリックでリアクションピッカーを開閉します。既存のリアクションチップをクリックするとそのリアクションをトグル（自分が付けていれば解除）できます。ホバーで誰がリアクションしたか確認できます。
- **その他メニュー**（「…」）: 以下を含みます。
  - 内容をコピー（本文があるノートのみ表示）
  - この投稿より前を取得（カラムのタイムラインに並んでいるノートでのみ表示）。このノートから、一覧で次に並んでいるノートに届くまで過去の投稿をサーバーから取得して、間の抜けを埋めます。すでに抜けが無ければ何も変わりません。一覧の一番下のノートで押した場合は、続きを1ページ取得します。ノートの抜けに気付いたときや、起動時のギャップ埋めを無効にしているときに使えます
  - お気に入り登録/解除
  - クリップに追加（既存クリップへの追加、または新規クリップを作成して追加）
  - 翻訳（接続先サーバーの翻訳機能で本文を翻訳し、投稿の本文の下に表示。サーバーで翻訳が設定されている場合のみ表示されます）
  - 削除（自分の投稿のみ表示）
  - Renote取り消し（自分が行った引用なしRenoteのカードでのみ表示）
- **投票**: 投票付きノートでは選択肢をクリックし、確認ダイアログで「投票する」を選ぶと投票できます。締切済み・投票済みの選択肢は無効化されます。
- **CW付きノート**: 「続きを見る」で本文を展開でき、展開後は「隠す」で再度隠せます。
- **返信先の表示**: カラムのタイムラインと通知カードでは、返信ノートの上に返信先のカードが表示されます。カードには返信先のアバター・表示名・`@ユーザー名`・投稿からの経過時間と、本文(改行を保ったまま最大3行)が出ます。返信先にCWがある場合は本文の代わりにCWの文言、本文がなくファイルだけの場合は「(1つのファイル)」「(N個のファイル)」、本文のないRenoteの場合は「(Renote)」と表示されます。アバターや表示名をクリックすると、返信先のユーザーのプロフィールが開きます。検索やプロフィールのモーダル、展開した引用では、従来どおり「↩ 返信」とだけ表示されます。返信先が削除されている・閲覧できないなどで取得できない場合も、カラムでは従来どおり「↩ 返信」とだけ表示されます(通知カードでは何も表示されません)。返信先がミュート設定(ローカルNG・サーバーミュート・ワードミュート)に該当する場合は、カードを出さず、従来どおり「↩ 返信」とだけ表示されます。返信ノート自体の表示・非表示は、これまでのミュート判定のままです。NGの設定を保存すると、表示中のノートと通知のカードにもすぐ反映されます。サーバー側のミュートやワードミュートの変更は、次に受信・読み込みするノートから反映されます。一度「↩ 返信」に戻ったカードは、ミュートを解除してもカラムを開き直すまで元に戻りません。

通知カード自体は表示専用ですが、mention/reply/renote/quote/reaction/pollEndedなど、ノートが紐づく通知にはそのノートがプレビュー表示され、上記のノート操作（返信・Renote・引用・リアクション・その他メニュー）をそのまま通知カードから行えます。

## 設定画面

設定画面の各セクションで以下を変更できます。

- **アカウント**: ログイン中アカウントの一覧、既定アカウントの切替、再認証、アカウントの削除、新規追加。
- **レイアウト**: UIモード（OSに合わせる/PC版/モバイル版）、新規カラムの既定幅、メディアサムネイルの高さ上限。
- **モバイル**: スマホ版でのみ表示されるタブ。ハプティクス（振動）のON/OFF。ONの場合、ノート投稿時とリアクション付与時に端末を振動させます（既定ON）。
- **外観**: テーマ（ライト/ダーク/OSに合わせる、プリセット、カスタムテーマの作成・編集）、コードハイライトテーマ、絵文字スタイル（Twemoji/Fluent Emoji/OS標準）、フォント、Instance Ticker（投稿者インスタンス表示。表示しない/リモートのみ/常に表示）、猫化（ユーザー設定に従う/全員を猫化/全員を人間化。ノート本文のにゃん語化とアバターの猫耳に反映）、アイコンの丸み（0～100%。アバター画像の角丸。既定20%）、UIスケール（50～200%。文字・余白・アイコン・画像を含むUI全体の拡大縮小。既定100%。デスクトップ版のみ）、MFMアニメーション（$[shake]等の装飾アニメーションのON/OFF）、カスタムCSS（任意のCSSをアプリ全体に適用。サイズの上限は256KiBで、超えると保存できません。Tailwindのクラスと同じ詳細度のルールは、より具体的なセレクタか `!important` を使わないと上書きできない場合があります。画面が壊れたときは[トラブルシューティング](#トラブルシューティング)を参照）。
- **背景**: 背景画像とその配置・基準点、暗さ、ぼかし、カラム不透明度。
- **リアクション**: 絵文字ピッカーの「ピン留め」タブに表示する絵文字の追加・削除・並べ替え。
- **外部連携**: MFM検索構文($[search]相当)で使う検索エンジンのURLテンプレート、投稿本文中のURLへのリンクプレビュー表示ON/OFFとカスタムsummalyプロキシURL、ノート翻訳の翻訳先言語。
- **データ**: ノートキャッシュの保持件数・保持日数・サイズの上限（いずれも0で無制限。超過分は古い順に自動削除）、起動時のギャップ埋め件数、ノートキャッシュの保存先バックエンド（SQLite（ローカル、既定）・PostgreSQL・MySQL/MariaDBから選択）。PostgreSQL/MySQL利用時はユーザー自身が用意した稼働中のインスタンス（ホスト・ポート・データベース名・ユーザー名・パスワード）への接続情報を入力します。切り替えは保存と同時に即座に反映され、アプリの再起動は不要です。接続に失敗した場合はエラーを表示し、切替前のバックエンドのまま維持されます。なお、ノートキャッシュのサイズ上限（MB）はPostgreSQL/MySQLバックエンドには効果がありません（保持件数上限・保持日数上限は引き続き有効です）。
- **通知**: デスクトップ通知・通知音のグローバルON/OFFと通知音の選択。実際に鳴るのは、このグローバル設定とタブ側の個別設定が両方ONのときです。通知音には MML で打ち込んだ音も選べます（上の「MML で通知音を作る」を参照）。
- **NG／ミュート**: NGワード（本文/CWへの部分一致）、NGユーザー、NGインスタンスをそれぞれ複数登録できます。保存後は以降受信するノート・表示中のノートの両方に適用されます。
- **Tsumugiについて**: バージョン・コミットハッシュ・ライセンス・リポジトリURLの表示。新しいバージョンが公開されている場合はバナーで通知されます。バージョン表示を7回タップすると「開発者オプション」タブが表示されるようになります（無効化する手段はありません）。
- **開発者オプション**: 「Tsumugiについて」タブのバージョン表示を7回タップすると表示されるタブ。動作ログをファイルに残す設定（デバッグ用、次回起動から反映）。

## トラブルシューティング

**Linux/Wayland（Hyprland等）で描画が壊れる／`Gdk Error 71 (protocol error)` が出る**

WebKitGTKのDMABUFレンダラがNVIDIAドライバの未対応バッファ形式を要求し、このエラーを起こすことがあります。tsumugiはLinuxでは既定で`__NV_DISABLE_EXPLICIT_SYNC=1`をセットしてHWアクセラレーションを維持したまま回避していますが、それでも解決しない場合は以下を試してください。

```sh
WEBKIT_DISABLE_DMABUF_RENDERER=1 ./tsumugi
```

（HWアクセラレーションは失われますが、より広範囲のケースを回避できます。それでも解決しない場合はX11バックエンドでの起動を試してください。）

```sh
GDK_BACKEND=x11 ./tsumugi
```

（開発ビルドを使っている場合は `cargo tauri dev` の前に同様に環境変数を付けてください。）

**カスタムCSSで画面が操作できなくなった**

環境変数 `TSUMUGI_SAFE_MODE=1` を付けて起動すると、カスタムCSSを適用せずに起動します（保存済みのCSSは消えません）。設定画面の「外観」→「カスタムCSS」で内容を直して保存し、通常どおり再起動してください。

```sh
TSUMUGI_SAFE_MODE=1 ./tsumugi
```

Androidでは環境変数を渡せないため、この方法は使えません。復旧するにはアプリのデータを消去するか、再インストールしてください。

**メディアの保存や音声の波形表示が「取得先が許可されていません」で失敗する**

セキュリティのため、メディアの保存と音声波形のための取得は、ローカルや社内ネットワーク(`localhost`、`192.168.x.x` など)のアドレスへは行いません。ログイン中のアカウントのインスタンスについては例外として許可されますが、インスタンスとは別のドメイン(メディア用CDNなど)がLAN内のアドレスに解決される構成では取得できません。なお、システムのプロキシを使っている環境では、この検証は一部しか効きません。
