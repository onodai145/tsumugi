# ESLint を CI に追加する Implementation Plan(Issue #707、PR 2/2)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** ESLint を入れて指摘を 0 にし、`frontend-check` と pre-push で `pnpm lint` を走らせる。

**Architecture:** 型情報なしの推奨ルール + Promise の 2 ルールだけ型情報を使う flat config。設定(Task 1)→ 掃除(Task 2・3)→ CI・フック・ドキュメント(Task 4)。

**Tech Stack:** ESLint 10、typescript-eslint 8、eslint-plugin-svelte 3、pnpm。

**Spec:** `docs/superpowers/specs/2026-11-26-issue-707-clippy-eslint-design.md`

## Global Constraints

- PR 1(clippy)のマージ後に、`git switch main && git pull` してから `chore/issue-707-eslint` を切る。
- アプリの挙動を変えない。`eslint --fix` は使わず手で直す。`catch` が要るなどバグと分かったものは直さず、ユーザーに報告して Issue にする。
- 型情報を使うルールは `no-floating-promises` と `no-misused-promises` の 2 つだけ。
- 行単位の無効化には `-- 理由` を書く。
- コミットは件名 1 行 + `Co-Authored-By` トレーラ。`--no-verify` は使わない。
- 下の行番号は main = 650050e のもの。ずれていたら `pnpm lint` の出力を使う。

## Review Focus

- `MuteSection.svelte` の `placeholder={"ネタバレ\nspoiler"}` の改行が残ること(Task 1 の設定で除外し、Task 3 で触らない)。
- `{#snippet children()}` を外したモーダルの中身が、そのまま表示されること(Task 3 Step 5 の `pnpm test`、CI の E2E)。
- `void` を足した箇所で、呼び出しの順序と回数が変わらないこと(式の前に `void` を足すだけにする)。
- 属性の `{'…'}` を外した後も、`&&` や `"` を含む文字列が同じに表示されること(Task 3 Step 2)。
- `vite.config.ts` の triple-slash を消した後も、`test` 設定の型が通ること(Task 3 Step 4)。
