# MML 構文の拡張(タイ・連符・コメントなど)の設計

Issue #499(関連: #75 / `2026-10-15-issue-75-mml-ringtone-design.md`、#494 / `2026-10-16-issue-494-mml-timbre-design.md`、#500 / `2026-10-17-issue-500-mml-editor-design.md`)

## 目的

長い曲や凝った曲を MML で書きやすくし、他の MML 方言との互換も上げる。#499 の「小さい」候補 6 つ(`^` タイ、相対音量、コメント、連符、ループの脱出とネスト、ゲートタイム `q`)を、1 つの spec・1 つの PR で入れる。

成功条件:

- 6 つの記法が、`parse_mml`(Rust)で解釈でき、誤りは今までどおり「N 文字目」の位置つきエラーで返る。
- 今まで通っていた MML は、同じ `MmlScore` になる(新しい記号は今は構文エラーなので、保存済みの MML の意味は変わらない)。
- エディタの色分け、入力補助キー、「記法」ヘルプ、ユーザーガイドが新しい記法に追随する。
- `NoteEvent` / `MmlScore` / レンダラー(`mmlRender.ts`)は変えない。

## 範囲

含める: 上の 6 つと、それに伴うフロントの追随(字句解析・使用量の数え方・入力補助キー・ヘルプ・ガイド)。

含めない(#499 に残す、または別 Issue に切り出す): 和音 `'ceg'`、変数・マクロ、トラック間のテンポ共有、音色のパラメータ、エフェクト、ドラムの割り当て(いずれも `NoteEvent` やレンダラーに波及する「中くらい」の候補)。連符の入れ子。`/` 単独・`#`・`;` をコメントにすること。コメント用の入力補助キー(`/` `*`)。

## 原典の確認結果(2026-10-20)

Issue 本文の元ネタを、各ライブラリの README とソースで確かめた。方言ごとに違う点は、tsumugi の既存規則(エラーは位置つき、保存済みの意味は変えない)に合わせて決めた。

| 連符 | `{ccc}8` は 3 音が 8 分音符 1 つ分の時間(MCK、ffmml)。sakuramml は長さを省略でき `{cde}`。tonejs-mml-to-json の README には記述が無い。 | MCK `mckc-e.txt`、ffmml `src/commands.rs`、sakuramml README |
| ループの脱出 | sakuramml の `[回数 内容]` で `:` を書くと、最後の回だけ `:` 以降を飛ばす。ネスト可(`[2 c [3 de] f]`)。ffmml のソースには脱出もネストも無い。mml-iterator は `/: ... \| ... :/n` という別の記法。 | sakuramml `docs/syntax-macro.md`、ffmml `src/commands.rs`、mml-iterator README |
| ゲート `q` | 尺度は方言ごとに違う。MCK は 1〜8(既定 8)、sakuramml は百分率(既定 90)、tonejs-mml-to-json は 0〜100(既定 95)、mml-iterator は既定 75(範囲は README に無い)。 | 各 README・仕様書 |

注意:

- mml-iterator では `[ ]` が和音で、tsumugi の繰り返しとは意味が違う。同じ記号で意味が違う方言があるので、互換は「主要な記法が通る」までを目標にする。
- MCK 仕様書の `^` の例は取得結果が崩れていて、細部は確認しきれていない。`^` の仕様は sakuramml と mml-iterator の記法を採る。
- MCK / ffmml の連符で、中の音符に長さを書いたときの扱い(長さの比で割るか、均等に割るか)は原典で確認できていない。下の仕様は「長さの比で割る」を採る。長さを書かない `{c d e}4` はどちらでも 3 等分で同じ。
- 連符の入れ子禁止と、ループとの交差の禁止は、実装を単純にするための tsumugi 側の制限(sakuramml は入れ子の連符を許す)。

## 決定事項

| 決定 | 内容 | 理由 |
|---|---|---|
| 変える層 | `mml.rs` のみ(パーサーと実行)。`NoteEvent` / `MmlScore` / レンダラーは変えない | 6 項目とも、音の列に落とし込める。型が変わらないので `tauri.gen.ts` も再生成しない |
| `q` の尺度 | 百分率 1〜100、既定 100 | sakuramml・tonejs-mml-to-json と同じ尺度で、既定を 100 にすれば保存済みの MML の音が変わらない |
| タイ `^` | 長さを足す。直前が音符のときだけ | `&` と同じ規則。休符の後ろは範囲外とする |
| 相対音量 | `v+n` / `v-n`、範囲外はエラー | `>` `<` がオクターブの範囲外でエラーになる既存の扱いに合わせる |
| 連符 | 入れ子禁止、長さの比で割る | 実装を単純にする |
| ループのネスト | 深さは無制限、展開後の命令数に上限 | 上限で十分に抑えられる |
| PR | 1 つの PR にまとめる | パーサーだけで済み、字句解析・ヘルプ・ガイドの更新が共通のため |

## 記法(v2)

v1(`2026-10-15-issue-75-mml-ringtone-design.md`)に、次を足す。v1 の記法・既定値・範囲は変えない。大文字小文字と空白は、今までどおり無視する。

| 項目 | 記法 | 規則 |
|---|---|---|
| タイ `^` | `c4^8`、`c4^`、`c4^8.` | 直前の音符に長さを足す。長さは数字+付点(省略時は `l` の値、付点は最大 2 個、数字は 1 2 4 8 16 32 64)。`&` と同じく、直前が音符のときだけ使える。先頭・休符の後ろ・`&` の直後は `^` の位置でエラー。`&` とは併用できる(`c4&c8^8`)。高さは同じなので、`&` のような高さの検査は要らない。 |
| 相対音量 | `v+n`、`v-n`、`v+`、`v-` | `n` は 1〜15、省略時は 1。結果が 0〜15 を出たら、`v` の位置でエラー(丸めない)。`n` が 0 や 16 以上のときは数字の位置でエラー。 |
| コメント | `// …`、`/* … */` | `//` は改行まで(改行そのものは空白として残る)。`/* */` は入れ子にできず、閉じ忘れは `/*` の位置でエラー。`/` 単独、`#`、`;` はコメントにしない(`;` はトラック区切り)。`/ /`(間に空白)は `//` ではなく、`/` の位置で「不明な文字」のエラー。コメントは文字数(5000)に含める。 |
| 連符 | `{c d e}4`、`{c d e}`、`{c d e}4.` | 括弧の中の音符・休符・タイの長さを合計し、`}` の後の長さ(省略時は `{` の時点の `l` の値。付点つきも可)に収まるように比例して縮める。`{ceg}4` は 3 音が四分音符 1 つ分の時間。中では `o` `>` `<` `l` `v` `@` `q` `t` `^` `&` が使える。入れ子は不可(`{` の位置でエラー)。`;` は含められない。ループとは、括弧が交差しない限り組み合わせられる(`{[c]2 e}4` と `[{c d e}4]2` は可、`{ [ } ]` は不可)。空の連符 `{}` は、`{` の位置でエラー。 |
| ループの脱出 | `[ a : b ]n` | `:` は 1 つのループに 1 個まで(2 個目は `:` の位置でエラー)。最後の回だけ `:` 以降を飛ばす。`n` 回なら「`a b` を n−1 回、最後に `a`」。ループの外の `:` は `:` の位置でエラー。 |
| ループのネスト | `[ [ a ]3 b ]2` | 深さは無制限。展開後の命令数が 50 万(`MAX_EXPANDED_OPS`)を超えたら、外側の `]` の位置でエラー。50 万は、v1 で最大の展開(ループ 1 組で本体が約 4996 文字、99 回の繰り返しで約 49.5 万命令)を弾かない値。音符・休符は 3000 音・90 秒の上限で抑えられるが、音を出さない命令(`o` `v` など)は抑えられないので、命令数そのものに上限を置く。 |
| ゲート `q` | `q80` | 1〜100、既定 100。範囲外・省略は `q` の位置、数字の範囲外は数字の位置でエラー。音符ごとに、鳴らす長さ = 全長 × q/100。タイでつないだ音は、全体の長さに掛ける。次の音の開始時刻(`t`)は、全長で進める。トラックごとに独立した状態で、`;` で戻る。 |

エラー位置の規則は v1 と同じで、すべて元の文字位置(コメントと空白を含む)の 0 始まりで返し、UI は 1 始まりの「N 文字目」で出す。

## 設計

### 1. 前処理: コメントの除去(`parse` の入口)

今の `parse` は、空白を落とした `(小文字の文字, 元の文字位置)` の列を作ってから、`;` でトラックに分ける。コメント内の `;` や、改行を必要とする `//` を扱うため、空白を落とす前に、元の文字列を文字位置つきで走査してコメントを落とす。

- `//` から改行の手前まで、`/* */` の両端を含む範囲を落とす。落とした文字は、空白と同じく、後続の文字位置をずらさない(位置は常に元のテキストの添字)。
- `/*` の閉じ忘れは `/*` の位置のエラー。
- コメント以外の `/` は、そのまま列に残り、`parse_track` が「不明な文字」にする。
- 文字数の上限(5000)の検査は、コメントを落とす前の元のテキストで行う。

### 2. `Op` の追加(`parse_track` / `run_track`)

追加する `Op`:

- `TieLen { len: Option<u32>, dots: u8 }`(`^`)
- `VolumeDelta(i8)`(`v+n` / `v-n`)
- `Gate(u8)`(`q`)
- `TupletStart` と `TupletEnd { len: Option<u32>, dots: u8 }`

`parse_track` の変更:

- ループと連符の「開き」を、1 つのスタックで管理する(要素は、ループの `[` の位置・出力の開始 index・`:` の位置、または連符の `{` の位置・出力の開始 index)。`]` のときスタックの先頭が連符なら、`{` が閉じていないエラー。`}` のときスタックの先頭がループなら、`[` が閉じていないエラー。これで交差が弾ける。連符の中でスタックに連符が積まれていれば入れ子エラー。
- `:` はスタックの先頭がループのときだけ受ける。その位置を、そのループの枠に記録する。
- `]` で、ループの本体 `out[start..]` を複製する。`:` が無ければ v1 と同じ(本体を n−1 回足す)。`:` があれば、本体を 前半 `A` と 後半 `B` に分け、`A B` を n−2 回足し、最後に `A` だけを足す(`n` は 2〜99 なので、n=2 は `A B A`)。足すたびに `out.len()` を見て、`MAX_EXPANDED_OPS` を超えたら `]` の位置でエラー。
- 連符の `{ … }n` の `n` と、`^` の長さは、`length_and_dots` を使って読む(長さの検査・付点の上限は v1 と同じ)。
- `v` の直後が `+` / `-` なら、`VolumeDelta`(数字省略なら 1)。それ以外は v1 の `Volume`。
- `q` は `Gate`(数字必須、1〜100)。

`run_track` の変更:

- 状態に `gate: u32`(既定 100)を足す。`TrackState` に、直前の音符の全長(拍の長さ)を保持するフィールドを足し、`notes[idx].duration_sec` は、全長 × 音符の作成時の gate / 100 で計算し直す(タイで延びるたびに、全長から計算する)。`t` は全長で進める。
- 連符: `TupletStart` に来たら、対応する `TupletEnd` までの命令(連符は入れ子にならないので、次の `TupletEnd`)を先読みする。その間の `l` の変更を追いながら、音符・休符・`^` の長さを拍単位(四分音符 = 1)で合計し、縮小率 = 括弧の長さ(拍) ÷ 合計 を得る。括弧の中の各音符・休符・`^` の長さは、拍 × 縮小率 × 60 / テンポ で秒にする。テンポの変更は縮小率の外で効く(縮小率は拍の比なので、テンポが途中で変わってもよい)。括弧の中が音符・休符・`^` を含まないとき(`{}` や `{o5}`)は、`TupletStart` の位置でエラー。
- 時間の上限(90 秒)・音数の上限(3000)の検査は、今までどおり音符・休符ごとに行う。

### 3. フロントエンド

- `lib/mmlComments.ts`(新規): 元のテキストからコメントを落とした範囲(または、コメントの範囲の列)を返す純粋関数。`mmlLexer.ts` と `mmlUsage.ts` が共通で使う。位置は UTF-16 の添字(エディタの装飾が使う)で扱い、Rust の文字位置との対応は `mmlPosition.ts` の既存の変換に任せる。
- `mmlLexer.ts`: トークン種別に `comment` を足し、コメントの範囲はそのままトークンにする。コメントの外では、空白を落とした記号列で動く現在の方式を保つ。`^` は `rest` と同じ種別(タイ)にする。`{` と `}n` は `repeat`、`:` は `repeat`、`q` は `command`(数字は `number`)。`v` の直後の `+` / `-` も `command` に含める(`v+2` は `command` と `number`)。
- `mmlEditorExtensions.ts`: `comment` に、既存のトークンの色とは別のスタイルを当てる(`docs/design/style-guide.md` に従い、一回限りの値は作らない)。
- `mmlUsage.ts`: `countTracks` は、コメントを落としてから `;` で分ける。文字数は、コメントを含む今までの数え方のまま。
- `mmlKeys.ts`: 「半音・付点・タイ」のグループに `^`、「繰り返し・トラック」のグループに `{` `}` `:` を足す。`mmlKeys.test.ts` の期待値を更新する。
- 「記法」ヘルプ(`SoundChoicePicker.svelte`)と `docs/guide/user-guide.md` の記法表を、新しい 6 つの記法に合わせて更新する。ガイドの記法の表に、`^`、`v+n` / `v-n`、`q`、`{ }`、`:`、ネスト、コメントを足し、5000 文字にコメントも含まれることを書く。
- サンプルは足さない(`mmlSampleData.json` はそのまま)。

### 4. エラー処理

- 新しい記法の誤りは、すべて `MmlError { position, message }` で返す(`parse_mml` はデータで返す)。保存時の検証(`validate_sound_choice`)と、再生時のフォールバック(`beep`)は、今までどおり。保存済みの MML が、将来このパーサーで通らなくなることはない(新しい記号は今まで構文エラーだった)。

## テスト

- Rust(単体、`mml.rs`):
  - `^`: 単体・複数連続・`l` の既定長・付点・`&` との併用・先頭や休符の後ろのエラー・位置。
  - `v+n` / `v-n`: 範囲・省略・範囲外・位置。
  - コメント: `//` の行末、`/* */`、閉じ忘れ、コメント内の `;` でトラックが分かれないこと、コメントを挟んだ音符の文字位置が元のテキストのままであること、`/ /` のエラー、5000 文字がコメントを含むこと。
  - 連符: `{c d e}4`、長さ省略、付点、長さの比(`{c4 d8}4`)、`l` の変更を含む連符、中の `^`、空の連符、入れ子、ループとの組み合わせと交差、`;` の混入。
  - ループ: `:` の脱出、ネスト、ネストの中の `:`、`:` が 2 個、ループ外の `:`、展開の上限(`MAX_EXPANDED_OPS`)、v1 で最大のループが通ること。
  - `q`: 範囲、タイとの組み合わせ、`q` が `t` を進めないこと、トラックごとの状態。
  - 既存の MML(`^` などを含まないもの)が同じ結果になること: 既存のテストが全部そのまま通ること。
  - `frontend_samples_parse_within_limits` はそのまま通る。
- フロント(Vitest): `mmlComments` の範囲(サロゲートペアを含む)、`mmlLexer` の新トークンとコメント、`mmlUsage` の `countTracks`、`mmlKeys` の表、`SoundChoicePicker` の「記法」ヘルプの追記、`mmlEditorExtensions` のコメントのスタイル。
- 実機(手動): Xvfb と隔離したインスタンス(`dbus-run-session`、短い XDG パス、`WAYLAND_DISPLAY` は unset)で、新しい構文を含む MML の入力・色分け・エラー表示・試聴を確認する。音が鳴ることは確認できない(Xvfb に音声デバイスが無い)。サブエージェントのレビューが通っても、この確認の代わりにはしない。

## 未確認・リスク

- MCK / ffmml の連符で、中の音符に長さを書いたときの扱いは、原典で確認できていない(「原典の確認結果」を参照)。
- 他方言との互換は、記法の一部に限る(`[ ]` の意味、ループの記法、`q` の既定値などが違う)。
- 連符の縮小は、拍を有理数でなく `f64` で扱う。浮動小数点の誤差は、既存の `TIME_EPS` の許容幅で吸収する。
- 展開後 50 万命令の上限は、v1 で通る最大のループ(約 49.5 万命令)を弾かないための値。上限いっぱいまで展開したときの `parse` の所要時間とメモリは、計画の最初のタスクで測って確認する(v1 でも同じ規模までは展開できる)。
