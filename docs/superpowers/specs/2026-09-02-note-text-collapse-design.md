# ノート本文の折りたたみ表示 設計

- 作成日: 2026-09-02
- 対象Issue: #252「本文が長過ぎるときに折りたたむ」
- 対象コンポーネント: `frontend/src/ui/NoteCard.svelte`

## 背景

現状 `NoteCard.svelte` はCW（Content Warning）による本文の表示/非表示切り替えは実装済みだが、CWが付いていない長文ノートはそのまま全文表示される。タイムライン上で1件の長文ノートがカラムを占有し、他のノートの視認性が下がる。

## 要件

- 本文（`inner.text`）の文字数が閾値を超える場合、初期状態では高さを制限して折りたたみ、「もっと見る」ボタンで全文展開できるようにする。
- 判定基準は文字数のみ（改行数は見ない）。閾値は **300文字**（固定値、設定画面での変更は本Issueの範囲外）。
- CWと折りたたみは独立した層として重ねる。CWが閉じている間は今まで通り本文自体が非表示。CWを開いた（または元々CWが無い）結果表示される本文が300文字を超える場合に、折りたたみを適用する。
- 引用Renoteのネスト表示（`NoteCard`が`quoted=true`で自分自身を子として描画するケース）にも同じ折りたたみを適用する。追加の分岐は設けず、既存の`Self`再帰にそのまま乗せる。
- 一度「もっと見る」で展開したら、その場で再び畳む操作は提供しない（CWのトグルとは異なり、往復させる必要性が薄いため）。

## UI

- 見た目はX/Twitter等でよく見られる「高さ制限 + 下部グラデーション + 展開ボタン」パターンを採用する。
- 折りたたみ中の本文コンテナに `max-height` を指定し `overflow:hidden` する。目安は約150px（`text-sm`・`leading-[1.42]`で9〜10行相当）。
- コンテナ下端に、サーフェス色から透明への下方向グラデーションを重ね、テキストが唐突に切れている印象を和らげる。
- グラデーションの上に「もっと見る」ボタンを配置する。見た目は既存の`cw-toggle`（`rounded-md border border-border`）を流用し、新規のborder-radius/色トークンは増やさない。
- 展開後は`max-height`とグラデーション・ボタンを取り除き、通常のブロックとして全文を表示する。

## 状態管理

- `NoteCard.svelte`内にローカル`$state`（例: `textExpanded`、初期値`false`）を持つ。
- 文字数判定用に `$derived`（例: `isLongText = [...text].length > 300`）を追加する。サロゲートペア（絵文字等）を1文字として数えるため配列展開でカウントする。
- 折りたたみ表示条件: `isLongText && !textExpanded`。
- ボタンクリックで`textExpanded = true`にするのみ（再折りたたみのUIは無し）。
- この状態は他のnote表示インスタンス（同じノートが複数カラムに出る場合など）とは独立でよい。リアクション同期のような一元管理は不要（純粋な表示上のUI状態のため）。

## 実装範囲

- 変更ファイルは`NoteCard.svelte`のみ。`{#if inner.text}`ブロックとその直下の`<style>`を変更する。
- MFMパース（`Mfm`コンポーネント）自体には手を入れない。折りたたみはMFM描画後の外側コンテナの高さ制御で行うため、MFM内部のリンクや絵文字レンダリングとは独立している。

## テスト

`NoteCard.test.ts` に以下を追加する:

- 300文字以下の本文では「もっと見る」ボタンが表示されないこと。
- 300文字を超える本文では初期状態で「もっと見る」ボタンが表示されること。
- ボタンをクリックすると全文が表示され、ボタンが消えること。
- CWと併用時、CWを開いた結果の本文が300文字を超える場合にも折りたたみが効くこと。
- 引用Renoteのネスト表示（`quoted=true`）でも長文の折りたたみが効くこと。

## 非対象（YAGNI）

- 閾値のユーザー設定化。
- 展開後に再度畳み直すUI。
- 改行数ベースの判定との併用。
