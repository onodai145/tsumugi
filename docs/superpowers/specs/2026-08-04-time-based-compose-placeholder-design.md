# 投稿欄プレースホルダーの時間帯変更 設計

Issue: #113

## 背景 / 目的

投稿欄 (`ComposeBar.svelte`) のプレースホルダーは現在固定文言
`いまどうしてる？（Ctrl+Enter で投稿）` のみ。時間帯に応じて文言を変え、
遊び心のある投稿体験にする。

## 仕様

### 時間帯区分（ローカル時刻 `Date.getHours()` 基準）

| 区分 | 時間範囲 |
|---|---|
| 深夜 | 0–4時 |
| 早朝 | 4–7時 |
| 朝 | 7–10時 |
| 昼 | 10–17時 |
| 夕方 | 17–19時 |
| 夜 | 19–24時 |

境界は「開始時刻を含み終了時刻を含まない」（例: 朝は7:00〜9:59）。

### 文言候補（各区分7パターン、ランダムに1つ表示）

- 深夜: こんな時間に何してるの？ / 寝なくても大丈夫？ / 宇宙と交信する時間帯 / まだ起きてるんですか / 静かな夜ですね / 夜更かしは程々に / こんな時間まで何を？
- 早朝: 早起きですね / 一日の始まり / 鳥より早い / おはようございます（早い） / 静かな朝ですね / 今日は何をしますか？ / 夜明け前ですね
- 朝: おはようございます / 今日も一日がんばりましょう / モーニングルーティン / 朝ごはんは食べましたか？ / 今日の予定は？ / 気持ちのいい朝ですね / 通勤通学中ですか？
- 昼: いまどうしてる？ / お昼はもう食べた？ / 早起きさんですね / 午後もがんばりましょう / 一息つきませんか？ / 今日の調子はどう？ / お昼寝したい時間ですね
- 夕方: お疲れさまです / 今日はどんな一日だった？ / 夕焼けを見ながら / 帰り道ですか？ / 一日お疲れさまでした / 夕食は何にしますか？ / 空が綺麗な時間ですね
- 夜: こんばんは / 今日もお疲れ様 / 夜はこれから / ゆっくりしていますか？ / 明日の準備はできましたか？ / 夜更けの時間 / おやすみ前のひととき

括弧書きの操作説明（Ctrl+Enter で投稿）は付けない。

### 再抽選タイミング

投稿欄のテキストが空になったタイミング（マウント直後の初期状態、および投稿後・クリア後）で再抽選する。
入力中に文言が変わって視線がちらつくことを避けるため、テキストが空でない間は再抽選しない。

### 設定によるON/OFF

追加しない。常時有効とする（YAGNI）。

## 実装方針

### 新規ファイル: `frontend/src/lib/composePlaceholder.ts`

- 時間帯ごとの文言候補を定数として定義
- `pickComposePlaceholder(date: Date = new Date()): string` をエクスポート
  - `date` の時刻から区分を判定し、候補配列からランダムに1件返す

### `frontend/src/ui/ComposeBar.svelte`

- `placeholder` を `$state(pickComposePlaceholder())` で保持
- `$effect` で `text` を監視し、`text === ""` になるたびに `placeholder = pickComposePlaceholder()` を実行
- `<textarea>` の `placeholder="いまどうしてる？（Ctrl+Enter で投稿）"` を `placeholder={placeholder}` に置き換え
- CW欄など他のプレースホルダーは変更しない

## テスト

`frontend/src/lib/composePlaceholder.test.ts` を追加。既存の `time.test.ts` と同様に
`vi.useFakeTimers()` / `vi.setSystemTime()` で時刻を固定し、以下を検証する。

- 各区分の境界値（0, 3, 4, 6, 7, 9, 10, 16, 17, 18, 19, 23時など）で、返り値がその区分の候補配列に含まれること
- 複数回呼び出した際に候補配列以外の値を返さないこと

## スコープ外

- 設定によるON/OFF
- サーバー時刻・タイムゾーン設定との連動（常にクライアントのローカル時刻を使う）
