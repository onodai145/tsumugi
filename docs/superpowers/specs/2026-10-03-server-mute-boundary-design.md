# サーバー側ミュートの解除をキャッシュ優先の backfill へ反映する 設計 (Issue #454)

Misskey 側でミュート(ユーザー、ワードミュート)を解除しても、キャッシュ優先の backfill が、解除したユーザーのノートを返さない問題を、「解除を検出したときだけ、そのアカウントのカラムの境界を捨てる」ことで直す。#228(ローカルのミュート変更時に境界を捨てる)、#452 / PR #453(`ColumnFence::invalidate_boundaries`)の続き。コードの読解による推定で、実際の再現は確認していない。

## 背景・原因

- カラムのキャッシュ(`column_note`)には、取得時のフィルタ(ローカル NG、サーバー側ミュート、ワードミュート)を通ったノートだけが入る(`FilteredFetch.cacheable`)。
- 境界(`column_source_boundary`。「この境界より新しい範囲は完全」)は `cache.db` に保存され、再起動をまたいで残る。境界を捨てるのは、カラムの編集・閉じる、ローカル NG の保存(`set_mute`)、キャッシュの上限による削除だけ。
- キャッシュ優先の backfill は、返す直前に**ミュートを再適用**する。したがって、ミュートの**追加**は、キャッシュ済みのノートを隠せる。しかし、ミュートの**解除**は、除外済みのノートがキャッシュに無く、読み直せない。
- ローカル NG は、変更時に境界を捨てて(#228)、この問題を避けている。サーバー側ミュートの同期(`sync_server_mutes`)には、その処理が無い。
- `sync_server_mutes` は、起動時(カラムの復元より**前**)と、アカウント追加・再認証時にだけ呼ばれる。定期同期は無い。

### 起きる流れ

1. 以前の起動中に、Alice(ミュート中)を除いたノートだけが、カラムのキャッシュに入り、境界が残る。
2. Misskey の Web 画面で、Alice のミュートを解除する。
3. tsumugi を再起動する。同期で、新しい(Alice を除いた)ミュート集合に差し替わる。
4. 上へスクロールすると、残っている境界を信じて、キャッシュだけで返す。境界の範囲内の Alice のノートが出てこない。

起動時の同期は、カラムの復元前なので競合しない。アカウント追加・再認証時は、カラムが開いて取得が走っている最中でありえるので、#452 と同じ競合も起きる。

## スコープ

- 対象: サーバー側ミュート(ユーザーのミュート/ブロック、`mutedWords`)の**解除**を検出して、そのアカウントのカラムの境界を捨てる。
- 対象外:
  - 定期同期(Web 側の変更は、起動か再認証まで反映されない)。
  - アカウント削除時の保存値の掃除(孤児は数KB以下)。
  - DB スキーマ、Tauri コマンドの署名、TS バインディング、フロントエンド。

## 設計

### 保存(`src-tauri/src/store/settings.rs`)

- `SettingsData` に `server_mute_snapshots: HashMap<String, ServerMuteSnapshot>`(アカウントID → 前回の集合)を、`#[serde(default)]` つきで足す。TS には出力されない(`Account` に足すとバインディングが変わるため、別マップにする)。設定の JSON のスキーマは後方互換(古いファイルは、空のマップとして読める)。
- `ServerMuteSnapshot { users: Vec<String>, words: Vec<String> }`。どちらも重複なし・ソート済み。`Serialize` / `Deserialize` / `Clone` / `Default` / `PartialEq` / `Debug`。
- `load_server_mute_snapshot(account_id) -> Result<Option<ServerMuteSnapshot>>` と `save_server_mute_snapshot(account_id, &ServerMuteSnapshot) -> Result<()>`(`load_mute` / `save_mute` と同じ書き方)。

### ワードルールの文字列表現(`src-tauri/src/filter/mute.rs`)

`WordMuteRule::key(&self) -> String` を足す。

- `Words(語群)`: 語を小文字にし、ソートして、区切り文字(`\u{1f}`)で連結し、先頭に `w:` を付ける(AND は順序に依らない)。
- `Regex(re)`: `r:` + `re.as_str()`。

既知の制限: `i` フラグは `RegexBuilder::case_insensitive` で適用されるので、`as_str()` に残らない。パターンが同じで、`i` フラグだけを外した(一致が減る)場合は、解除として検出できない。極端な端の例として、制限として受け入れる(カラムの編集、またはローカル NG の保存で直る)。

### 同期の流れ(`src-tauri/src/commands/mute.rs` の `sync_server_mutes_core`)

1. ユーザー(`fetch_muted_and_blocked`)とワード(`fetch_muted_words`)を取得する。どちらかの失敗は、何も変えずに `Err`(現状どおり)。
2. 新しい集合から、`ServerMuteSnapshot`(ユーザーIDをソート、ワードを `key()` でソート)を作る。
3. `state.set_server_mutes` / `state.set_server_word_mutes` で、**メモリ上の集合を新しいものに差し替える**。
4. 前回の保存値を読む(`load_server_mute_snapshot`)。
   - **無い**(アップグレード直後、新しいアカウント): 境界は捨てず、保存だけする。
   - **解除がある**(前回の `users` または `words` の要素で、今回の集合に無いものがある): そのアカウントのカラムの境界を捨てる(下記)。**成功したら**、保存値を更新する。
   - **増えただけ、または変化なし**: 境界は捨てない。変化があれば、保存値を更新する。
5. 境界を捨てる処理: `state.column_fence.invalidate_boundaries(|| async { ... })` の中で、`state.settings.load_columns()` を `account_id` で絞った各カラムに、`state.cache.replace_fetch_boundaries(&column.id, &[])` を実行する(カラムごとの削除として使える。バックエンドに新しい API は要らない)。1件でも失敗したら、残りのカラムも実行した上で、全体を失敗として扱う。

編集された1つのルール(語の追加・削除、正規表現の変更)は、「古いキーが消え、新しいキーが増えた」ので、解除として検出する(安全側)。

### 不変条件(#452 と同じ)

ミュート集合の差し替え(手順3)は、`invalidate_boundaries`(手順5)より**前**に行う。書き込み側は、ミュート設定を読む(フィルタする)前に世代を控えるので、境界の世代が進んだ時点で、新しい集合がすでに反映されている。これで、アカウント追加・再認証のように、取得が走っている最中でも、旧い集合の結果に基づく境界を書き込めない(#452 の `ColumnFence` が守る)。

`invalidate_boundaries` は、全カラム共通の境界の世代を進めるので、他のアカウントの実行中の取得も、境界の書き込みを1回飛ばす。飛ばすのは安全側(境界が未確定になるだけ)なので、許容する。

### 判断: 保存値が無いときは、捨てない

- 理由: アップグレード直後に、全ユーザーの全カラムで、キャッシュ優先の backfill が一斉に止まるのを避ける。境界を再確立するのは `open_stream_and_fetch`(新規カラム、編集、キャッシュが空のカラムの復元)だけで、`extend` は既存の行しか延長しないので、一度捨てると、開き直すまで効かない。
- 代償: アップグレード前に、すでにたまっていた古さ(Web で解除済みだが、再同期していないもの)は、直らない。そのカラムを編集して開き直すか、ローカル NG の設定を保存すれば直る。
- 代案: 保存値が無ければ、1回だけ、そのアカウントの全カラムを捨てる。

### エラー

- 境界の破棄(DB)が失敗したら、保存値を**更新しない**。次回の同期で、もう一度解除を検出して、再試行する。同期の戻り値(`SyncMuteResult`)は、取得に成功していれば `Ok`(現状どおり)。ログに `warn` を出す。
- 保存値の書き込み(設定ファイル)が失敗しても、同期は失敗にしない(ログのみ)。次回、もう一度検出するだけで、捨てるのは安全側。

## 検討した代替案

- **指紋(ハッシュ)だけを保存し、変わったら必ず捨てる**: 保存は小さいが、ミュートを追加しただけでも捨てるので、キャッシュ優先が効かなくなる頻度が増える。ハッシュの実装(新しいクレートか、標準の `DefaultHasher`。後者は、Rust のバージョンで変わりうる)も決める必要がある。
- **起動のたびに全部捨てる**: キャッシュ優先の backfill が、再起動のたびに効かなくなる。#228 の趣旨を壊す。
- **保存値をキャッシュ DB のテーブルに持つ**: 3バックエンドのスキーマ変更とマイグレーションが要る。設定の JSON で足りる。

## テスト

- `WordMuteRule::key()` の単体テスト: 語の順序と大文字小文字に依らない。`Words` と `Regex` の衝突が無い(`w:` / `r:` の接頭辞)。
- 設定の往復: `save_server_mute_snapshot` → `load_server_mute_snapshot` で同じ値が返る。古い設定ファイル(`server_mute_snapshots` が無い)を読める。
- `sync_server_mutes_core` の結合テスト(既存のテストと同じ、wiremock の `mute/list` / `blocking/list` / `i` と、メモリ上の設定・キャッシュ):
  - 保存値が無い → 境界は捨てず、保存値が作られる。
  - 増えただけ(ユーザー/ワード) → 境界は捨てない。保存値は更新される。
  - ユーザーが減った → そのアカウントのカラムの境界が空になる。**他のアカウントのカラムは、そのまま**。
  - ワードが減った → 同様に空になる。
  - 取得に失敗 → 何も変わらない(境界も、保存値も、メモリ上の集合も)。
  - 境界を捨てた後、境界の世代が古い書き込み(`ColumnFence` の `boundaries_ok` が偽)は、境界を書かない(#452 の機構が効くこと)。
- 変異確認: 解除の検出を外す(常に「増えただけ」と扱う)と、「減った」系のテストが落ちること。

## 影響範囲

- 変更するファイル: `src-tauri/src/store/settings.rs`、`src-tauri/src/filter/mute.rs`、`src-tauri/src/commands/mute.rs`。
- DB スキーマ、Tauri コマンドの署名、TS バインディング、フロントエンドは変わらない。設定ファイルに、後方互換のフィールドが1つ増える。

## 後続の候補(本設計では扱わない)

- 定期同期(Web 側の変更を、起動や再認証を待たずに反映する)。
- `i` フラグだけの変更の検出(`WordMuteRule::Regex` に、元の文字列かフラグを持たせる)。
- アカウント削除時の保存値の掃除。
