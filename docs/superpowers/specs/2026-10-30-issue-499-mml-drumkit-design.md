# MML のドラムの割り当て `@drumkit` の設計

Issue #499 の残りの候補のうち、「ドラムの割り当て」。関連: `2026-10-16-issue-494-mml-timbre-design.md`(音色 `@`、`drum` と `noise`)、`2026-10-20-issue-499-mml-chord-design.md`(和音)。

## 目的

今の `@12 drum` は、書いた音の高さがそのまま膜の音の高さになる(タムのような音)。キック・スネア・ハイハットなどを、1 つのトラックの中で音の高さによって打ち分けて、ドラムパートを書けるようにする。

成功条件:

- `@drumkit o2 c4 d4 f+8 f+8 ...` のように、GM(General MIDI)のドラムと同じ高さで、キック・スネア・ハイハットなどが鳴る。
- 今まで通っていた MML は、同じ `MmlScore` になり、同じ音で鳴る(`@12 drum` と `@13 noise` は変えない)。
- `NoteEvent` / `MmlScore` / `MmlError` の形は変えない。変わるのは `Timbre` の値が 1 つ増えること(`tauri.gen.ts` は再生成される)。

## 範囲

含める:

- 新しい音色 `@14 drumkit`(音の高さで楽器を打ち分ける)。
- それに伴う、Rust(`Timbre`、名前の読み取り)、フロント(音源、「記法」ヘルプ、音色ボタン)、ユーザーガイドの追随。

含めない:

- `@12 drum` と `@13 noise` の変更。
- オープンハイハットをクローズドで止める動作(チョーク)。
- GM のパーカッションのうち、ラテン系やホイッスルなど(下の「割り当てる音」にないもの)。
- 楽器ごとのパラメーター(音程・減衰の調整)、サンプル曲。

## 原典の確認結果(2026-10-30)

GM のパーカッションの割り当ては、Finale のマニュアル「General MIDI Percussion MIDI Map Table」(`https://usermanuals.finalemusic.com/Finale2011Mac/Content/Finale/General_MIDI_Percussion_Map_Table.htm`)で、35〜81 の全項目を確認した。MML の他の方言(ffmml、sakuramml など)の、ドラムの割り当ての書き方は、今回は調べていない。

GM では、チャンネル 10 のノート番号が楽器に対応する(35 = Acoustic Bass Drum、36 = Bass Drum 1、…)。tsumugi の高さは `midi = 12 × (オクターブ + 1) + 半音` で、`o2 c` = 36、`o4 c` = 60。GM の 35〜81 は `o1 b` 〜 `o5 a` に収まり、すべて書ける(`o` は 1〜8)。

## 決定

| 項目 | 決定 | 理由 |
|---|---|---|
| 新しい音色か、`drum` の置き換えか | 新しい音色 `@14 drumkit` | `@12 drum` を使った保存済みの MML の聞こえ方を変えないため。 |
| 名前 | `drumkit` | 一般的な言い方(drum kit)で意味が分かる。`kit` だけでは `drum` の隣で何の kit か分かりにくい。 |
| 割り当ての基準 | GM のドラムのノート番号(下の表) | 他のツールと同じ感覚で書ける。 |
| 割り当てのない高さ | 鳴らさない(休符と同じ。エラーにしない) | 他の音色と同じ MML を貼っても、誤った楽器が混ざらない。 |
| 音の長さ | 書いた長さは無視して、楽器ごとの固定の長さで鳴らす | 打楽器は叩いたら減衰する。`q` も、実質効かない。 |
| 音量 | `v`(音量)は効く。1 音ごとのベロシティとして渡す | 他の音色と同じ。 |
| チョーク | 入れない | 範囲を絞る。後から足せる。 |

### 割り当てる音(GM のノート番号 → 楽器)

| 楽器 | GM の番号 | MML での書き方 |
|---|---|---|
| キック | 35, 36 | `o1 b`, `o2 c` |
| サイドスティック | 37 | `o2 c+` |
| スネア | 38, 40 | `o2 d`, `o2 e` |
| ハンドクラップ | 39 | `o2 d+` |
| タム(低い順の 6 段) | 41, 43, 45, 47, 48, 50 | `o2 f`, `o2 g`, `o2 a`, `o2 b`, `o3 c`, `o3 d` |
| クローズドハイハット | 42, 44 | `o2 f+`, `o2 g+` |
| オープンハイハット | 46 | `o2 a+` |
| クラッシュシンバル | 49, 57 | `o3 c+`, `o3 a` |
| ライドシンバル | 51, 59 | `o3 d+`, `o3 b` |
| ライドベル | 53 | `o3 f` |
| カウベル | 56 | `o3 g+` |

上にない GM の番号(52、54、55、58、60〜81)と、35〜81 の外の高さは、鳴らさない。タム以外は、同じ楽器の複数の番号を同じ音で鳴らす(35 と 36、38 と 40、42 と 44、49 と 57、51 と 59)。タムの 6 段は、高さの違う音で鳴らす。

### 名前の読み取り: `drum` が `drumkit` の接頭辞になる

今の Rust の読み取り(`timbre_name`)は、名前の表の先頭から順に、名前に一致するものを選ぶ。「どの名前も他の名前の接頭辞ではない」ことをテストで保証し、一致が 1 つに決まる前提になっている。`drum` は `drumkit` の接頭辞なので、この前提が崩れる。

- 読み取りを**最長一致**に変える(一致する名前のうち、最も長いものを選ぶ)。フロントの字句解析(`mmlLexer.ts` の `timbreNameLen`)は、もともと最長一致なので変えない。
- 既存の MML の意味は変わらない。`@drum` の直後に `kit` と続く MML は、`k` が命令にないので、今までも構文エラーだった。`@drumkit` は今まで構文エラーで、これから音色になるだけ。
- 「名前が互いに接頭辞でない」テストは、「接頭辞の組は `drum` と `drumkit` だけで、`drumkit` の `drum` を除いた残り(`kit`)は命令の先頭になれない」に置き換える。

## 音の作り方

`mmlTimbres.ts` の `Voice` の `trigger` に、5 つ目の引数として `midi`(ノート番号)を足す。ほかの音色は無視する。`drumkit` は、`midi` から楽器を選ぶ(`hz` から逆算しない)。`mmlRender.ts` は、`n.midi` を渡すだけを変える。

| 楽器 | 音源(Tone.js) | 備考 |
|---|---|---|
| キック、タム | `MembraneSynth`(`PolySynth`) | 楽器ごとに 1 つ作って使い回す。タムは高さを変える。 |
| スネア、ハンドクラップ、ハイハット | `NoiseSynth` + ハイパスフィルタ(スネアは短い膜の音を重ねてよい) | `NoiseSynth` は単音用なので、1 打ごとに作る(`noise` と同じ)。 |
| クラッシュ、ライド、ライドベル、カウベル | `MetalSynth` | 単音用なので、1 打ごとに作る。 |
| サイドスティック | 短い減衰の `MembraneSynth` か、短いノイズ | 実装中に鳴らして決める。 |

- 楽器の細かい音作り(減衰の長さ、フィルタ、周波数)は、実装中に Tone.js の `Tone.Offline` で実際に描画して決める。
- 楽器の固定の長さ(減衰とリリースの合計)は、`TAIL_SEC`(0.6 秒)以下にする。最後の音の余韻が切れないため。
- 音量は、`drumkit` 全体で `fm` の聞こえる大きさ(RMS)に合わせて校正する(`2026-10-16-issue-494-mml-timbre-design.md` と同じ方法)。1 打のピークは 0.36 以下にする。楽器どうしの相対音量は、実測の RMS をおおむねそろえる。**聞こえ方の良し悪しは、音声デバイスのない環境では判断できない。** 実際に聴いたユーザーの評価で、後から直す前提。
- 和音 `'cf+'` は、各音が別々に鳴るので、キックとハイハットが同時に鳴る(追加の実装は要らない)。

## Rust の変更

- `domain/mml.rs`: `Timbre::Drumkit` を足し、`ALL` を 15 個にし、`name()` に `"drumkit"` を足す。
- `mml.rs`: `timbre_name` を最長一致にする。`@14` が通り、`@15` 以上は今までどおりエラー(位置は番号の先頭)。
- `tauri.gen.ts`: `cargo test` の `generates_frontend_bindings` で再生成される(`Timbre` の和に `"drumkit"` が増える)。手で編集しない。

## フロントの変更

- `mmlTimbres.ts`: `drumkit` の音源、`Voice.trigger` の `midi` 引数。
- `mmlRender.ts`: `trigger` に `n.midi` を渡す。
- `SoundChoicePicker.svelte`: 音色の一覧は `TIMBRE_LIST` から作られるので、`@14 drumkit` のボタンが増える。「記法」に、割り当て表の要約を足す。
- `docs/guide/user-guide.md`: 音色の一覧に `drumkit` を足し、割り当て表を載せる。

## テスト

- Rust: 15 種の番号と名前の対応(`TIMBRE_TABLE`)、`@drumkit` / `@14` の読み取り、`@drum c` と `@drumkit c` の読み分け(最長一致)、`@drumkitc` が `drumkit` + `c`、`@15` のエラー位置、接頭辞の組が `drum` と `drumkit` だけであること。
- フロント(Vitest): `EXPECTED` の表(15 種)、GM の番号 → 楽器の表(表にある全番号が楽器に対応し、表にない番号は鳴らさないこと)、`mmlRender` が `midi` を `trigger` に渡すこと、`drumkit` が割り当てのない高さを鳴らさないこと、ヘルプ・音色ボタン。
- 実機(手動、隔離した Xvfb): 15 種すべてが、エラー・NaN なしで描画できること。`drumkit` の各楽器の 1 打のピークが 0.36 以下で、RMS を測った値を spec に残すこと。割り当てのない高さが無音になること。3000 音すべてを `drumkit` で鳴らしたときの描画時間を測ること。**音が鳴ること自体は確認できない。**

## 未確認・リスク

- `MetalSynth` が、WebKitGTK の `Tone.Offline` で正しく描画できるか、実測するまで分からない。ダメなときは、シンバルとカウベルを、ノイズとオシレーターの組み合わせに替える。
- 1 打ごとに音源を作る楽器(スネア・ハイハット・シンバル類)で、3000 音を鳴らしたときの描画時間と、メモリ。測って、遅すぎるなら、ハイハットなど頻出の楽器だけでも使い回す方法に替える。
- 楽器どうしの音量バランスと音の質は、耳で聴かないと決まらない。最初の版は、実測の RMS をそろえた値で出して、聴いた人の指摘で直す。
- `Voice.trigger` の引数が増える。`Voice` を実装しているのは `mmlTimbres.ts` だけだが、`mmlRender.test.ts` のモックの引数も追随させる。
