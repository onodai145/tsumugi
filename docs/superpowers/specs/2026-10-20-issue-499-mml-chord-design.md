# MML の和音 `'ceg'` の設計

Issue #499 の「中くらい」の候補のうち、「和音の記法」。関連: `2026-10-15-issue-75-mml-ringtone-design.md`、`2026-10-20-issue-499-mml-syntax-extension-design.md`(PR #511。`^` `q` 連符など)、`2026-10-20-issue-499-mml-shared-tempo-design.md`(PR #513。`t=`)。

## 目的

今の MML は、1 つのトラックでは 1 音ずつしか書けない(同時に鳴らすにはトラックを分けるしかなく、上限は 4)。1 つのトラックの中で、複数の音を同時に鳴らす記法を足す。

成功条件:

- `'ceg'4.` のように、1 つのトラックで和音を書け、誤りは今までどおり「N 文字目」の位置つきエラーで返る。
- 今まで通っていた MML は、同じ `MmlScore` になる(`'` は今は構文エラーなので、保存済みの MML の意味は変わらない)。
- `NoteEvent` / `MmlScore` / `MmlError` / `tauri.gen.ts` / レンダラー(`mmlRender.ts`)は変えない。

## 範囲

含める: `'…'` の和音と、それに伴うフロントの追随(字句解析・入力補助キー・「記法」ヘルプ・ユーザーガイド)。

含めない:
- 和音と `&` の組み合わせ(エラーにする。長くしたいときは `^`)。
- 和音の中の音ごとの長さ・休符・音量などのコマンド。
- 和音の名前(`C` `Am7` など)や、和音のマクロ・省略記法。
- ストラム(音をずらして鳴らす)。

## 原典の確認結果(2026-10-20)

| 方言 | 確認できた内容 | 出典 |
|---|---|---|
| sakuramml | 単引用符で囲んで同時に鳴らす。`'ceg'8`(長さは閉じの `'` の**後ろ**)、`'c>c'`(オクターブ違いも書ける)。`'ceg'4,90,120`(後ろに音長・ゲート・ベロシティ)。 | `docs/syntax-macro.md`(和音) |
| mml-iterator | `[ … ]` で囲む。中は音符と `<` `>`、長さは閉じの `]` の後ろ(`[ >g<ce ]2`)。省略時は `l`。`[ ]` は tsumugi ではループなので使えない。 | README |
| tonejs-mml-to-json | `'ceg'`、`'c4eg'.`(長さは引用符の中の最初の音符の直後、付点は外)。変換先は `PolySynth`。 | README |
| MCK / ffmml | 和音の記法は無い(MCK ガイドは、速いアルペジオで和音を近似する方法を挙げている)。 | `mck_guide_v1.0.txt` |

分かったこと: 引用符(sakuramml、tonejs)か括弧(mml-iterator)で囲む点は共通で、長さを閉じの後ろに書くのが 2 つ(sakuramml、mml-iterator)。tsumugi の `{ }n` や `[ ]n` と同じ形なので、これに合わせる。

## 決定

| 項目 | 決定 | 理由 |
|---|---|---|
| 記法 | `'ceg'4.`(長さと付点は閉じの `'` の後ろに 1 つ。省略時は `l`) | sakuramml と同じ。`{cde}4` や `[…]3` と同じ「閉じの後ろに長さ」の形で一貫する。tonejs の「最初の音符の直後」は、長さと付点が離れ、最初の音符だけ長さが違うと誤解されやすい。 |
| 中に書けるもの | 音符(`#` `+` `-` つき)と `<` `>` だけ | `'c>c'` のようなオクターブ違いの和音を書けるようにするため。休符・長さ・他のコマンドは意味が曖昧になる。 |
| 中の `<` `>` | 和音の間だけ効き、和音の後ろは元のオクターブに戻る(`o4 'c>c' d` の `d` は o4) | 和音の中でオクターブを跨いでも、後続の音符の高さがずれない。書き忘れでずれる事故を防ぐ。 |
| 音量 | 各音の `velocity` を、和音の音数で割る(`'ceg'` の各音は `v` の音量の 1/3) | レンダラーは同じトラックの同時発音を足し合わせる(`PolySynth`)ので、割らないと合計が単音の音数倍になり、WAV で頭打ち(歪み)になりうる。複数トラックをトラック数で割っている今のやり方と同じ考え方。`NoteEvent` を変えずにパーサーだけで済む。 |
| `&` との組み合わせ | 不可(エラー) | 同じ高さの音どうしをつなぐ規則を、和音の音の組に広げると、規則とテストが増える。`^` で足りる。 |
| 音数の上限 | 和音の各音を 1 音として数える(3000) | `NoteEvent` の数が上限の根拠(レンダラーの負荷)なので、和音の音数も数える。 |

## 構文と意味

| 書き方 | 意味 |
|---|---|
| `'ceg'` | c・e・g を、現在のオクターブ・`l` の長さで同時に鳴らす。 |
| `'ceg'4.` | 長さ 4 の付点(和音全体の長さ)。 |
| `'c>c'` | 現在のオクターブの c と、1 つ上の c。和音の後ろのオクターブは元に戻る。 |
| `'c#e-g'` | `#` `+` で半音上げ、`-` で半音下げ(音符と同じ)。 |
| `'ceg'4^8` | `^` は、直前の和音の全部の音を延ばす。 |
| `q50 'ceg'4` | `q` は和音の全部の音に効く。 |
| `{'ce'4 d4}2` | 連符・ループの中に書ける(和音は連符の中で 1 つの長さとして数える)。 |

意味の詳細:
- 全部の音が同じ開始時刻・同じ長さ(`q` を掛けた長さ)で、書いた順に `NoteEvent` になる。時間は和音の長さ(`q` を掛ける前の全長)だけ進む。
- 同じ音を重ねて書いても(`'cc'`)エラーにしない(2 つの `NoteEvent` になる)。1 音だけの和音(`'c'`)も書ける。
- 各音の `velocity` は `v` の音量 ÷ 15 ÷ 音数。
- 和音の中の `<` `>` のオクターブの範囲(1〜8)の検査は、今までと同じ(超えたら、その `<` `>` の位置でエラー)。

誤りと位置(0 始まりの文字位置で、エラー表示は 1 始まりの「N 文字目」):

| 入力の例 | エラー位置 | 内容 |
|---|---|---|
| `'ce`(閉じていない) | 開きの `'` | 閉じていない `'` があります |
| `''`(空) | 開きの `'` | 和音の中に音符が必要です |
| `'cr'` / `'c[e]2'` | `r` / `[` | 和音の中には音符と `<` `>` だけ書けます |
| `c 'c4e'`(中に数字) | 数字 | 和音の長さは、閉じの `'` の後ろに書いてください |
| `'ceg'3`(長さが不正) | 数字 | 長さは 1, 2, 4, 8, 16, 32, 64 のいずれかです(今までと同じ) |
| `c&'ceg'` / `'ceg'&c` | `&` | `&` は和音とは組み合わせられません(長くしたいときは `^` を使ってください) |
| `o8 'c>c'` | `>` | オクターブは 1〜8 です(今までと同じ) |
| `'ce;g'` | 開きの `'` | `;` でトラックが分かれ、閉じていない `'` になる(連符 `{ }` と同じ) |
| 音数の超過 | 超えた最初の音の位置 | 音符は 3000 個までです(今までと同じ) |

## 設計

Rust は `src-tauri/src/mml.rs` だけを変える。レンダラー(`mmlRender.ts`)は変えない: `noise` 以外のすべての音色は `PolySynth` で作られていて、`noise` は音ごとに作る方式なので、同じトラックの同時発音にすでに対応している。

- `Op` に `ChordStart` / `ChordNote { semitone }` / `ChordEnd { len, dots }` を足す(連符の `TupletStart` / `TupletEnd` と同じ作り)。`parse_track` が、`'` から `'` までを読み、中の音符を `ChordNote`、`<` `>` を既存の `OctaveUp` / `OctaveDown` にし、閉じの後ろの長さと付点を `ChordEnd` に持たせる。`ChordStart` の位置は開きの `'`。
- `run_track` は、`ChordStart` でオクターブを控え、`ChordNote` で音を溜め、`ChordEnd` で、音数で割った音量の `NoteEvent` を同じ開始時刻で出し、長さだけ時間を進め、控えたオクターブに戻す。
- 「直前の音符」の状態(`last_note`)を、和音の全部の音の `notes` の添字を指すように広げ、`^` が全部の音を延ばし、`&` は和音の前後でエラーにする。休符は今までどおり状態を消す。
- 連符の縮小率を求める関数と、連符の `}` の検査(中に音符か休符が要る)、`t=` の置き場所の検査(最初の音符・休符より前)は、`ChordEnd` を 1 つの長さとして数える。
- 展開後の命令数の上限(`MAX_EXPANDED_OPS`)は、和音の命令も数える(今までと同じ仕組み)。

フロント:
- `lib/mmlLexer.ts`: `'` を構造の記号(`repeat`)として色分けする。閉じの `'` は、後ろの長さ・付点まで 1 つのトークンにする(`}4.` と同じ)。中の音符と `<` `>` は、今までどおりの色。
- `lib/mmlKeys.ts`: 構造のグループに `'` のキーを足す(ソフトキーボードで切り替えが要るため。`{` `}` と同じ理由)。
- `ui/settings/SoundChoicePicker.svelte` の「記法」ヘルプと、`docs/guide/user-guide.md` に和音を足す。

## テスト

- Rust(`mml.rs`): 和音の基本(音・開始時刻・長さ・書いた順)、長さと付点と `l` の既定、音量が音数で割られること、`#` `-`、中の `<` `>` と、和音の後ろのオクターブが元に戻ること、`^` で全部の音が延びること、`q`、連符・ループとの組み合わせ(連符の中で 1 つの長さとして数えること)、`t=` の置き場所(和音の後ろは不可)、1 音の和音・同じ音の重ね書き、音数の上限に和音の各音が数えられること。誤り(上の表の各行)の位置。和音を含まない既存のテストが全部そのまま通ること。
- フロント(Vitest): `mmlLexer` の `'…'4.`(開きと閉じ、中の音符・`<` `>`、長さ・付点)、`mmlKeys` の `'` キー(キーだけで打った列に読めない文字が残らないこと)、`SoundChoicePicker` のヘルプに和音が出ること。
- 実機(手動): Xvfb と隔離したインスタンスで、和音を含む MML の入力・色分け・エラー表示・試聴(`play_notify_sound` に渡る値)を確認する。音が鳴ること・和音の聞こえ方は確認できない(Xvfb に音声デバイスが無い)。

## 未確認・リスク

- 音量を音数で割ると、和音は同じ `v` の単音より小さく聞こえる。「1/音数」が聞こえ方として適切かは、耳では確かめられない。
- `@noise`(音程を無視する音色)で和音を書くと、音数ぶんの同時のノイズが、割った音量で鳴る(音程の違いは出ない)。意味のある使い方ではないが、エラーにはしない。
- 和音の音が多い MML は、音数の上限(3000)に早く届く。
- 長い余韻の和音が、次の和音と重なる聞こえ方も、耳では未確認(今までも、余韻は重なる)。
- 他方言との互換: `'ceg'4`(sakuramml)と一致するが、sakuramml の `'ceg'4,90,120`(後ろのゲート・ベロシティ)と、tonejs の `'c4eg'`(長さが中)は一致しない。

## 実装後の確認

2026-10-20、`feat/issue-499-mml-chord` の HEAD 6a36bd6 で確認した。実アプリは Xvfb(:97)・`dbus-run-session`・隔離した XDG_*(/tmp 直下の小さなファイルだけ)で起動し、`WAYLAND_DISPLAY` は unset した(実画面には出していない)。設定にはダミーのアカウント(`misskey.invalid`)だけを書いた。入力は xdotool による実際のキー入力。

確認できたこと:
- 自動テスト: `cargo test` は 780 passed / 0 failed / 61 ignored(`mml::` は 82 件)、`pnpm check` は 0 errors(既存の `UrlPreviewCard.svelte` の警告 1 件のみ)、`pnpm test` は 97 files / 1042 tests passed。`git status` は空で、`tauri.gen.ts` は変わっていない。
- `rustfmt --check src/mml.rs`: 差分は 5 箇所で、すべて `main` にも既にある(増えていない)。
- 3000 音ちょうどの和音と、ループで 3000 を超える入力(`chord_counts_each_note_toward_the_limit`): テスト 1 件の所要は 0.00 秒(debug のテストビルド)。
- 実アプリ(隔離インスタンス。設定→通知で「通知音を鳴らす」ON、種類「MML（打ち込み）」):
  1. `'ceg'4 'dfa'4 'ceg'2`: 構文エラーなし、「再生時間 2.0 秒」、文字 20/5000・音 9/3000・トラック 1/4。開きの `'` と、閉じの `'4` `'2` が構造の色(`mml-repeat`)になった。
  2. `o4 'ce`(閉じていない): 「4 文字目: 閉じていない `'` があります」。試聴・保存は `disabled`。「4 文字目」を押すとカーソルが `'` の手前(添字 3)に移った。
  3. `c&'ceg'`(2 文字目、`&` は和音とは組み合わせられません)、`'cr'`(3 文字目、和音の中には音符と `<` `>` だけ書けます)、`''`(1 文字目、和音の中に音符が必要です)、`c 'c4e'`(5 文字目、和音の長さは、閉じの `'` の後ろに書いてください)、`'ceg'3`(6 文字目、長さが不正)で、それぞれ位置つきのエラーが出て、保存・試聴が `disabled` になった。
  4. 「記法」に、`'ceg'4 和音(同時に鳴らす。…)` の行が出た(`<` `>` が文字で出ている)。
  5. 試聴: `fetch` の `ipc://` を記録した。`parse_mml` の後に `play_notify_sound` が呼ばれ、`choice` は `data:audio/wav;base64,UklGR…`(152,975 文字。同じ 2.0 秒の曲だった `t=` の確認と同じ大きさ)。「試聴に失敗しました」は出ず、ログに WARN / ERROR / panic はなかった。

確認できなかったこと:
- 実際に音が鳴ること、和音の聞こえ方(音量を音数で割った聞こえ方を含む。Xvfb に音声デバイスが無い)。値(開始・長さ・音の数・再生時間)はテストで確認した。
- 入力補助キー `'` の実機での押下(モバイル UI の画面は確認していない。キーだけで打った列の字句解析はテストで確認した)。
- Android の実機・エミュレーター、macOS / Windows。

気づいたこと:
- 直接ビルドしたデバッグバイナリは、`frontend/dist` を埋め込む(ページの URL が `tauri://localhost`)。dev サーバーが動いていないときは、`pnpm build` で dist を作り直してから `cargo build` し直さないと、古いフロントで動く(最初はこれで `'` が色分けされなかった)。dist は git の管理外。

### レビュー後の修正

全体レビューで、和音の直後の `^` が、そのたびに和音の全部の音の長さを書き直していて(音数ぶんのループ)、`^` を大量に展開した入力で遅くなるという指摘があった。3000 音の和音の後ろに、連符で縮めた `^` を約 49 万個並べた入力(約 3000 文字)で、debug のテストビルドで 19.7 秒かかった(レビュアーの測定は debug 11.5 秒、release 相当 1.6 秒)。`^` では「延ばした長さがまだ書かれていない」印と全長だけを更新し、次の音符・和音・休符・トラックの終わりで、直前の音符・和音へ 1 回だけ書くようにした(`flush_last`)。同じ入力は 0.04 秒で、回帰テストを足した。
