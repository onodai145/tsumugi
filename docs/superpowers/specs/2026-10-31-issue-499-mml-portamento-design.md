# MML のポルタメントの設計

Issue #499 の残りの候補のうち、「音色のパラメータ」の最後の 1 つ、ポルタメント。関連: `2026-10-30-issue-499-mml-timbre-params-design.md`(`y` `m` `k`。そこで「仕組みが違う」として別の PR にした)、`2026-10-16-issue-494-mml-timbre-design.md`(音色 `@`)、`2026-10-20-issue-499-mml-macro-design.md`(`$` マクロ)。

## 目的

前の音から次の音へ、音の高さを滑らせて入る表現を、MML で書けるようにする。今は、隣り合う音の高さは必ず階段状に変わる。

成功条件:

- `p80 c4 e4 g4 p0 c4` のように、トラックの状態として書け、誤りは今までどおり「N 文字目」の位置つきエラーで返る。
- 今まで通っていた MML は、同じ音になる(`p` は今は構文エラーの文字なので、保存済みの MML の意味は変わらない)。
- 打楽器(`drum` `noise` `drumkit`)の音は変わらない。
- `p` を使った MML の描画が、使わない同じ長さの MML より極端に遅くならない(デチューンのときの教訓。下の「描画」)。

## 範囲

含める:

- コマンド `p`(滑る時間)。
- それに伴う、Rust(パーサー、`NoteEvent`)、フロント(音源、字句解析、入力補助キー、「記法」ヘルプ)、ユーザーガイドの追随。

含めない:

- 本物のレガート(1 つの声を鳴らし続けて、エンベロープを再度かけずに高さだけ変える)。滑る音も、頭からアタックする。
- 音ごとに滑る時間を変える書き方、`&` で違う高さをつなぐ書き方(`c&e`)。「状態型の `p`」だけにする(ユーザーが選んだ)。
- 和音からの・和音へのグリッサンド。
- 滑り方の曲線の選択(直線・指数など)。1 通りに決める。
- 原典(sakuramml の `Slur(SLUR_PORT, 長さ)` と `&`)との互換。標準はないので、tsumugi の記法は自分で決める(`2026-10-30-issue-499-mml-timbre-params-design.md` の「原典の確認結果」を参照)。

## 決定

| 項目 | 決定 | 理由 |
|---|---|---|
| 記法 | 1 文字コマンド `p<ミリ秒>`。`p0` で解除 | `y` `m` `k` と同じ形。マクロ・ループの中でも使え、1 つの概念で済む。`p` は今は構文エラーの文字。 |
| 状態 | トラックの状態。書いたところから後の音に効く。ループ・マクロ・連符の中でも書ける。和音の中には書けない(和音の前に書く) | `t` `v` `q` `y` `m` `k` と同じ。 |
| 範囲 | 1〜1000 ミリ秒(整数)。解除は `p0` | 実用の滑りは数十〜数百ミリ秒。1 秒を超えると「滑り」ではなく別の表現。 |
| 滑る音 | 下の「どの音が滑るか」の 4 条件をすべて満たす音だけ | 休符をはさんだら新しいフレーズ。和音には「前の高さ」が 1 つに決まらない。 |
| 滑り方 | 新しい音は、いつもどおり頭からアタックする。音の高さだけが、前の音の高さから目的の高さまで、**音程(セント)が直線的に**動く(周波数では指数的) | 音程が等速で動くのが、聞こえ方として自然。エンベロープには手を付けない。 |
| 長い滑り | 滑る時間が音の長さ(ゲート後)より長いときは、音の長さに縮める(音が消えるまでに、目的の高さに着く) | 目的の高さに着かない音は、書いた音と別の音程に聞こえる。 |
| NoteEvent | 音ごとに `glide: Option<Glide { from_midi: u8, ms: u16 }>` を持たせる(滑らなければ `None`) | 描画側が、音ごとに「どこから、何ミリ秒で」を知る必要がある。 |
| 音源の組 | `glide` は音源の組の鍵に入れない | デチューンで、組を増やす方式は 201 通りで描画が 169 秒かかった(`2026-10-30-issue-499-mml-timbre-params-design.md` の「実装後の確認」)。`p` を使う曲では、ほとんどの音が滑る。 |

## 記法と意味

`p<ミリ秒>`。例:

```
p80 c4 e4 g4 p0 c4   e は c から、g は e から 80ms で滑る。最後の c は滑らない。
p80 c4 r4 e4         休符をはさむので、e は普通に鳴る。
p80 c4 c4            同じ高さなので、滑らない。
p80 c&c e            タイでつないだ後の音 e は、c から滑る。
```

### どの音が滑るか

次の 4 つをすべて満たす音:

1. 滑る時間が 0 でない(`p` で 1〜1000 を書いた後)。
2. 直前が、休符をはさまない**単音**である(和音の直後・休符の直後・トラックの先頭は滑らない)。
3. 直前の音と高さが違う(同じ高さは何もしない)。
4. その音も、直前の音も、旋律の音色である(`drum` `noise` `drumkit` は `p` を無視する)。

補足:

- 「休符をはさまない」は、MML 上の位置で決める。`q` でゲートを短くして、直前の音が先に消えていても、滑る(休符を書いていないため)。
- 直前の音の音色(`@`)が違っても、滑る(高さは、音色と関係なく決まる)。音源は別になるので、前の音が滑って次の音に変わるのではなく、新しい音が前の高さから入る。
- タイ `&` と `^` で延びた音の高さは、延ばす前と同じ。その後の音は、その高さから滑る。
- 滑る音の `glide.from_midi` は、直前の音の MIDI ノート番号。
- 和音を閉じた後の音は、滑らない。
- `p` を書いても、音色を切り替えたとき(`@`)は、保たれる(`y` `m` `k` と同じく、トラックが持つ)。

### 他の命令との関係

- **`k`(デチューン)**: 滑る前後の高さの両方に、同じ倍率 `2^(セント/1200)` を掛ける。
- **`m`(ビブラート)・`y`(エンベロープ)**: 独立。ビブラートは音源の出力に挟むので、そのままかかる。エンベロープは、新しい音の頭から通常どおり始まる。
- **マクロ `$`**: 本体にも書ける(文字の置き換えなので)。
- **ループ `[ ]`**: ループの 2 周目の先頭の音は、1 周目の最後の音から滑る(ループは展開されるため)。
- **連符・`q`・`l`**: 音の長さを変えるだけで、`p` とは独立。

## エラー

| 入力 | 位置 | メッセージ(案) |
|---|---|---|
| `p` の後に数字がない | `p` | `p` の後に数値が必要です |
| 範囲外(1001 以上) | 数字の先頭 | ポルタメントの時間は 1〜1000 ミリ秒です(`p0` で解除) |
| 和音の中の `p` | その文字 | 和音の中には書けません(和音の前に書いてください) |

和音の中のエラーは、既存の `y` `m` `k` のメッセージに `p` を足して、同じ文にする。

## Rust の変更

- `domain/mml.rs`: `NoteEvent` に `glide: Option<Glide>` を足す。`Glide { from_midi: u8, ms: u16 }`(`serde(rename_all = "camelCase")`、`specta::Type`)。`tauri.gen.ts` は再生成される(`glide: Glide | null` が増える)。`domain/mod.rs` の再エクスポートに足す。
- `mml.rs`: `Op::Portamento(u16)`、`TrackState` に `portamento_ms: u16`、パース(`p`)、和音の中のエラー(既存の `'y' | 'm' | 'k'` の腕に足す)、通常の音符(タイの延長でないもの)を作るときに、直前の単音(`last_notes[0]`、`!last_chord`)から `glide` を決める。和音の音と、タイで延びる音には載せない。
- 既存のテストで `NoteEvent` を直接組み立てている箇所は、`glide: None` を足す。

## フロントの変更

### 描画

- `Voice.trigger` に引数 `glide?: { fromHz: number; sec: number }` を足す(`renderScore` が、`fromHz` に `k` の倍率を掛け、`sec` を音の長さ以下に縮めて渡す)。打楽器の音源は無視する。
- 旋律の音源は、`Tone.PolySynth` に渡す声のクラスを、**周波数を滑らせられる継承クラス**に替える。`Synth` `FMSynth` `AMSynth` `DuoSynth` `MonoSynth` は、どれも `Monophonic` で、`frequency` の信号を持つ。継承クラスは、`Monophonic.setNote(note, time)` を上書きし、その時刻に滑る指定があれば、周波数を `fromHz` に置いて、`time + sec` までに `toHz` へ指数的に変える(指定が無ければ元の `setNote`)。
- 滑る指定は、`renderScore` が `trigger` する時に、音源ごとの `Map<時刻, { fromHz, sec }>` へ入れ、声が `setNote` で取り出して消す。`PolySynth` は同じ時刻の鳴らしを、同じトラックの同じ音源には 1 つしか持たない(和音の音は滑らない)ので、時刻が鍵になる。
- Tone の `portamento` プロパティは使わない(同じ声が鳴り続けているときだけ効く。`PolySynth` は音ごとに別の声を使う)。
- 音源の組の鍵は変えない(`glide` を入れない)。

### その他

- 字句解析(`mmlLexer.ts`): `p` を command、後ろの数字を number にする。
- 入力補助キー(`mmlKeys.ts`): 「音色パラメーター」のグループに `p` を足す(マクロのキーより前に並べる。`$c` の直後に `p80` が来ると、マクロ名 `cp80` と読まれるため)。
- 「記法」ヘルプ、ユーザーガイド: 書き方と範囲、「どの音が滑るか」を足す。

## テスト

- Rust: `p` の読み取りと範囲(1・1000・0・1001)、エラーの位置(数字なし・範囲外・和音の中)、トラックごとの独立、ループ・マクロの中、`glide` が付く条件の 4 つ(休符の後・和音の後・同じ高さ・打楽器・トラックの先頭・`p0` の後は付かない)、タイの後・`q` と連符の中、音色が違う音どうし、`NoteEvent` の `glide`(滑らなければ `None`)、`drum` と同時に `p` を書いても影響しないこと、既存の MML の結果が変わらないこと。
- フロント(Vitest): 字句解析(`p80` `p0`)、`mmlKeys`、`renderScore` が `glide` を `trigger` に渡すこと(`k` の倍率が掛かること、音の長さより長い滑りは縮むこと、打楽器は渡さないこと)、継承した声が、指定のある時刻だけ周波数を滑らせること(偽の Tone)、ヘルプ。
- 実機(手動、隔離した Xvfb): `p80 c4 e4` と `c4 e4` の WAV の周波数の軌跡を測って、80ms で c から e へ滑ること(音程が等速であること)。15 種の音色で、描画がエラー・NaN なしであること。極端な値(`p1000`、音が 1000ms より短い)。`p` を付けた 2772 音の描画時間(付けない場合と比べる)。**音が実際に鳴ること(聞こえ方の良し悪し)は、音声デバイスがないので確認できない。**

## 未確認・リスク

- **声のクラスを継承して `setNote` を上書きする方法は、実装の最初に実測で確かめる(最初のタスク)**。確かめること: (a) 5 種の声すべてで、周波数が実際に滑ること(`FMSynth` の `harmonicity`・`DuoSynth` の 2 つの声を含む)、(b) `Monophonic.triggerAttack` が `setNote` を呼ぶ順序と、同じ時刻の信号イベントの扱い、(c) `PolySynth` が声を再利用するとき(終わった声を別の音に使う)に、前の滑りの信号が残らないこと。うまくいかなければ、設計の見直し(別の方法、または範囲の縮小)を、ユーザーに相談する。
- 滑る音もエンベロープをやり直すので、本物のレガートとは聞こえ方が違う。ゲートを `q100` にして、前の音のリリースを 0 にしても、アタックの立ち上がりが聞こえる。
- 滑る音のピーク(0.36 以下)と RMS は、滑らない音と同じ波形のはずだが、実測で確かめる。
- `p` の文字は、将来の命令(パン `p` は他の MML 方言で一般的)との兼ね合いで変えたくなるかもしれない。tsumugi にパンは無いので、今回は決める。
