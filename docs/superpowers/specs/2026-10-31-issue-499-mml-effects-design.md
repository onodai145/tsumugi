# MML のエフェクト(リバーブ・ディレイ)の設計

Issue #499 の最後の候補、「エフェクト」。関連: `2026-10-30-issue-499-mml-timbre-params-design.md`(`y` `m` `k`)、`2026-10-31-issue-499-mml-portamento-design.md`(`p`。トラックの状態という形はこれに倣う)、`2026-10-16-issue-494-mml-timbre-design.md`(音色 `@`)。

## 目的

MML で書いた着信音に、リバーブ(残響)とディレイ(やまびこ)を付けられるようにする。今は、各音源がそのまま出力へつながっていて、トラックごとに音を束ねる場所がない。

成功条件:

- `x30,2000 z25,300,40 c4 e4 g4 x0 z0 c4` のように、トラックの状態として書け、誤りは今までどおり「N 文字目」の位置つきエラーで返る。
- 今まで通っていた MML は、同じ音になる(`x` `z` は今は構文エラーの文字なので、保存済みの MML の意味は変わらない)。エフェクトを使わない MML の描画は、長さも音も変わらない。
- 残響・やまびこの尾が切れずに入る(描画の長さを、必要なだけ延ばす)。
- エフェクトを足しても、1 発のピークが 0.36 以下、複数トラックの合計が 1.0 を超えない。
- `x` `z` を使う MML の描画が、使わない同じ長さの MML より極端に遅くならない(デチューンのときの教訓。下の「描画」)。

## 範囲

含める:

- コマンド `x`(リバーブ)と `z`(ディレイ)。
- それに伴う、Rust(パーサー、`NoteEvent`)、フロント(トラックのバス、エフェクト、音源の作成関数、字句解析、入力補助キー、「記法」ヘルプ)、ユーザーガイドの追随。

含めない:

- トラックをまたぐ共有のエフェクト(全体に 1 つのリバーブなど)。送りはトラックごとに決める。
- リバーブの種類(部屋・ホールなど)や、プリディレイ、ディレイのフィルターなど、上の引数以外の調整。
- ステレオ。出力は今までどおり 22050 Hz のモノラル。
- 他のエフェクト(コーラス、ディストーションなど)。
- 原典(他の MML 方言)との互換。標準はないので、tsumugi の記法は自分で決める。

## 決定

| 項目 | 決定 | 理由 |
|---|---|---|
| 記法 | `x 量,残響の長さ`(リバーブ)と `z 量,間隔,繰り返し`(ディレイ)。解除は `x0` / `z0`(0 を 1 つ) | `y a,d,s,r` と `m 速さ,深さ` と同じ形。`x` `z` は今は構文エラーの文字。 |
| 状態 | トラックの状態。書いたところから後の音に効く。ループ・マクロ・連符の中でも書ける。和音の中には書けない(和音の前に書く) | `t` `v` `q` `y` `m` `k` `p` と同じ。 |
| 範囲 | リバーブ: 量 1〜100(%)、長さ 100〜5000(ミリ秒)。ディレイ: 量 1〜100(%)、間隔 50〜1000(ミリ秒)、繰り返し 0〜90(%)。すべて整数 | 5 秒を超える残響は着信音には長すぎる。繰り返し 90% を超えると、減らずにいつまでも鳴る。間隔の上限は Tone のディレイの最大(1 秒)に合わせる。 |
| 効く音 | すべての音色(打楽器を含む) | スネアにリバーブは自然。`y` `m` `k` `p` は音高の話なので打楽器を除くが、エフェクトは音の話。 |
| 効き方 | 「音ごとに、エフェクトへ送る量」を、その音が始まる時刻に切り替える。元の音(ドライ)は常にそのまま出力へ行く | リバーブの長さやディレイの間隔は、描画中に時刻つきでは変えられない(下)。送る量なら、時刻つきで変えられる。 |
| エフェクトの組 | **(トラック, エフェクト, 長さ・間隔・繰り返し)の組ごとに、別のエフェクトを作る**。リバーブの組は長さで、ディレイの組は(間隔, 繰り返し)で決まる。各音の始まりに、その音の組の送りだけを量にし、同じトラックの他の組の送りを 0 にする | 音源の組(トラックごとのパラメーター違い)と同じ考え方。 |
| 組の数の上限 | 1 トラックにつき、リバーブ 4 種・ディレイ 4 種。5 種目の組を書いた命令を構文エラーにする | リバーブは作るたびにインパルス応答(下)を計算する重い処理で、組の数に比例して重くなる。デチューンの教訓(201 通りで 169 秒)。 |
| NoteEvent | 音ごとに `reverb: Option<ReverbParams { level: u8, decay_ms: u16 }>` と `delay: Option<DelayParams { level: u8, time_ms: u16, feedback: u8 }>` を持たせる(効かせない音は `None`) | 描画側が、音ごとに「どの組に、どれだけ送るか」を知る必要がある。 |
| 余韻(尾) | 描画の長さ = 曲の長さ + 尾。尾は、使ったエフェクトの尾の最大(最大 5 秒で頭打ち)。何も使わなければ、今の `TAIL_SEC`(0.6 秒) | 残響・やまびこが切れずに入るため。90 秒の上限は、今までどおり曲の長さにかかる(尾は外)。 |

## 記法と意味

```
x30,2000                    量 30%、残響 2 秒のリバーブ。
z25,300,40                  量 25%、間隔 300ms、繰り返し 40% のディレイ。
x0 z0                       どちらも解除。
@lead x30,2000 c4 e4 g4 x0 c4   最後の c だけ、リバーブなし。
```

- **書いた後の音から効く**。`x30,2000 c4` の c から。同じ音の途中では変わらない。
- **量が 0 になる**(`x0`)と、送りを 0 にする。すでに鳴っているエフェクトの尾は、自然に消えるまで続く(打ち切らない)。
- **組が違えば別のエフェクト**: `x30,2000 c4 x30,500 e4` の c は長さ 2 秒の組へ、e は長さ 0.5 秒の組へ送る。c の尾は、2 秒の組の中で続く。
- 同じ組に戻したとき(`x30,2000 c4 x30,500 e4 x30,2000 g4`)は、最初に作った 2 秒の組を使い回す(新しく作らない)。
- 他の命令との関係:
  - **`@`(音色)**: 切り替えても保たれる(`y` `m` `k` `p` と同じく、トラックが持つ)。
  - **`k` `y` `m` `p`**: 独立。
  - **マクロ `$`・ループ `[ ]`・連符・`q`・`l`**: 音の長さや並びを変えるだけで、`x` `z` とは独立。ループの 2 周目の先頭は、1 周目の最後の状態を引き継ぐ(ループは展開されるため)。
- 複数トラック: トラックごとに別々に書き、別々の組を持つ。複数トラックでも、トラック数で割る音量は変わらない。

## エラー

| 入力 | 位置 | メッセージ(案) |
|---|---|---|
| `x` `z` の後に数字がない | その文字 | `x` の後に数値が必要です |
| `x` の 0 以外の単独の数(`x30`)、`z` の 1 つ・2 つだけの数 | その場所 | `x` は `x0`(解除)か `x 量,長さ`(2 つの数)です / `z` は `z0`(解除)か `z 量,間隔,繰り返し`(3 つの数)です |
| 範囲外 | 数字の先頭 | リバーブの量は 1〜100 です / 残響の長さは 100〜5000 ミリ秒です / ディレイの量は 1〜100 です / ディレイの間隔は 50〜1000 ミリ秒です / 繰り返しは 0〜90 です |
| 組の数が上限(5 種目) | その `x` / `z` | 1 トラックに書けるリバーブは 4 種類までです(長さが違うものを数えます) / ディレイは 4 種類までです(間隔・繰り返しが違うものを数えます) |
| 和音の中の `x` `z` | その文字 | 和音の中には書けません(和音の前に書いてください)(既存の `y` `m` `k` `p` のメッセージに足して、同じ文にする) |

`x` / `z` の読み取りは、`y` / `m` と同じ流れ(最初の数を読み、`,` が続けば残りの数を `comma_numbers` で読む)にする。

## Rust の変更

- `domain/mml.rs`: `NoteEvent` に `reverb: Option<ReverbParams>`、`delay: Option<DelayParams>` を足す。`ReverbParams { level: u8, decay_ms: u16 }`、`DelayParams { level: u8, time_ms: u16, feedback: u8 }`(`serde(rename_all = "camelCase")`、`specta::Type`)。`tauri.gen.ts` は再生成される(`reverb: ReverbParams | null` と `delay: DelayParams | null` が増える)。`domain/mod.rs` の再エクスポートに足す。
- `mml.rs`: `Op::Reverb(Option<ReverbParams>)`、`Op::Delay(Option<DelayParams>)`、`TrackState` に `reverb` と `delay`、パース(`x` `z`)、和音の中のエラー(既存の `'y' | 'm' | 'k' | 'p'` の腕に足す)、通常の音符(タイの延長でないもの)と和音の各音に、そのときの `reverb` / `delay` を載せる。組の数(長さ、(間隔, 繰り返し))の数え上げは、パースで行う。
- 既存のテストで `NoteEvent` を直接組み立てている箇所は、`reverb: None, delay: None` を足す。

## フロントの変更

### 描画

- **トラックのバス**: 音源は、トラックごとの `Tone.Gain`(バス)につなぎ、バスは出力へつなぐ(ドライ)。エフェクトを 1 つも使わないトラックは、今までどおり音源を出力へ直接つなぐ(つなぎ方を変えない)。
- **音源の作成関数**: `TimbrePreset.create(Tone, volumeDb, params?)` に 4 つ目の引数 `out?`(つなぐ先の Tone のノード)を足す。省略時は今までどおり出力(テストを壊さない)。15 の音色が、`toDestination()` の代わりに `out` へつなぐ。
- **エフェクト**: エフェクトを使うトラックは、バスから、組ごとに「送りの Gain → エフェクト → 出力」を作る。リバーブは `Tone.Reverb`(`decay` = 長さ。`wet` = 1。生成が非同期なので `await reverb.ready` する)。ディレイは `Tone.FeedbackDelay`(`delayTime`、`feedback`、`wet` = 1、`maxDelay` = 1)。
- **送りの切り替え**: 各音の `startSec` で、その音の組の送り Gain を `量 / 100` に、同じトラックの他の組の送り Gain を 0 にする(`gain.setValueAtTime`)。直前の同じトラックの音と同じ状態なら、重ねて設定しない。
- **音量**: リバーブの出力は畳み込みで音量が変わるので、リバーブの出力に補正(固定の dB)をかける。補正の値は、実装の最初に測って決める(「未確認・リスク」)。
- **余韻(尾)**: `renderScore` の描画の長さを、`(score.totalSec ?? 0) + tail` にする。`tail` は、実際に量が 0 でない音が使った組の尾の最大。リバーブの尾 = 長さ + プリディレイ(0.01 秒)。ディレイの尾 = 間隔 × (繰り返し回数 + 1)、繰り返し回数 = 音量が 1/1000 に下がるまでの回数(`ceil(ln 0.001 / ln(繰り返し))`、繰り返し 0 なら 0)。どちらも最大 5 秒で頭打ち。使わなければ `TAIL_SEC`(0.6 秒)のまま。尾は `TAIL_SEC` 以上にする。
- **非同期**: `Tone.Offline` は、コールバックの完了を待つ(`yield callback(context)`)ので、コールバックを `async` にして、リバーブの `ready` を待ってから音を鳴らす。
- Tone のリバーブは、減衰するノイズからインパルス応答を作るので、**描画のたびに音が少し変わる**(ノイズ系の音色と同じ)。

### その他

- 字句解析(`mmlLexer.ts`): `x` `z` を command、後ろの数字を number にする(`,` は既存の扱い)。
- 入力補助キー(`mmlKeys.ts`): 「音色パラメーター」のグループに `x` `z` を足す(マクロのキーより前に並べる。`$c` の直後に `x30` が来ると、マクロ名と読まれるため)。
- 「記法」ヘルプ、ユーザーガイド: 書き方と範囲、効き方(書いた後の音から)、組の数の上限、描画が少し長くなることを足す。

## テスト

- Rust: `x` `z` の読み取りと範囲(各引数の下限・上限・その外)、`x0` / `z0`、エラーの位置(数字なし・単独の数・範囲外・和音の中・5 種目)、トラックごとの独立、ループ・マクロ・連符・タイの中、`NoteEvent` の `reverb` / `delay`(書いたものが付き、`x0` の後は `None`)、和音の各音に同じものが付くこと、打楽器にも付くこと、同じ組に戻るときは数えないこと、既存の MML の結果が変わらないこと(`reverb: None, delay: None`)。
- フロント(Vitest): 字句解析(`x30,2000` `z25,300,40` `x0`)、`mmlKeys`、`renderScore`: エフェクトなしの描画の長さが変わらないこと、使ったときの尾(リバーブ・ディレイ・頭打ち・両方使ったときの最大)、組ごとの送りの切り替え(偽の Tone で、`setValueAtTime` の時刻と値)、同じ組の使い回し、ヘルプ。
- 実機(手動、隔離した Xvfb): WAV を測って、(a) 量 0 とエフェクトなしで同じ音であること、(b) リバーブで音が `decay` 付近まで続くこと(終端が切れていないこと)、(c) ディレイのエコーが間隔ごとに現れ、繰り返しの割合で減ること、(d) 複数トラック・打楽器・15 種の音色で、描画がエラー・NaN なし、ピーク 1.0 以下であること、(e) 組を最大(4 種 + 4 種)使った 2772 音の描画時間(使わない場合と比べる)、(f) 描画が終わること(`Reverb` の非同期が詰まらないこと)。**音が実際に鳴ること(聞こえ方の良し悪し)は、音声デバイスがないので確認できない。**

## 未確認・リスク

- **`Tone.Reverb` が `Tone.Offline` の中で動くこと(最初のタスク)**。確かめること: (a) コールバックを `async` にして `await reverb.ready` した後に鳴らした音に、残響が付くこと、(b) 複数のリバーブ(4 種 × 複数トラック)を作っても、順に生成されて詰まらないこと、(c) インパルス応答は `OfflineContext` の標準のサンプルレート(コンテキストのレート)で作られ、22050 Hz に合っていること。うまくいかなければ、設計の見直し(別のリバーブ、または範囲の縮小)を、ユーザーに相談する。
- **ドライとウェットの音量差**: リバーブの補正値、ディレイの最大の量での合計ピークは、実測で決める。決められなければ、送りの上限(100% で 1.0 未満)を設計書へ戻して見直す。
- **尾が 5 秒で打ち切られること**: 繰り返し 90% のディレイは、間隔 1 秒だと 5 秒より長く続く。最後が突然切れる可能性がある(5 秒の端にフェードをかける対応は、必要なら実装で足す。足す場合は設計書へ戻す)。
- **90 秒の曲 + 尾 5 秒**: 描画の長さが最大 95 秒になり、保存・再生の経路(`data:` URL の大きさなど)が、90.6 秒を前提にしていないか、実装の最初に確かめる。
- **`x` `z` の文字**: 将来の命令との兼ね合いで変えたくなるかもしれない。tsumugi にほかの候補がないので、今回は決める。
