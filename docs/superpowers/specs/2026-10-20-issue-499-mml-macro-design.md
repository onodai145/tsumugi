# MML のマクロ `$name={…}` の設計

Issue #499 の「中くらい」の候補のうち、「変数・マクロ」。関連: `2026-10-15-issue-75-mml-ringtone-design.md`、`2026-10-20-issue-499-mml-syntax-extension-design.md`(PR #511)、`2026-10-20-issue-499-mml-shared-tempo-design.md`(PR #513)、`2026-10-20-issue-499-mml-chord-design.md`(PR #514)。

## 目的

同じフレーズを何度も書くと、5000 文字の上限をすぐ使い切る。フレーズに名前を付け、あとから名前で呼び出せるようにして、文字数を節約し、直すときも 1 か所で済むようにする。

成功条件:

- `$riff={c d e f}` で定義し、`$riff` で展開できる。誤りは今までどおり「N 文字目」の位置つきエラーで返る。
- 今まで通っていた MML は、同じ `MmlScore` になる(`$` は今は構文エラーなので、保存済みの MML の意味は変わらない)。
- `NoteEvent` / `MmlScore` / `MmlError` / `tauri.gen.ts` / レンダラー(`mmlRender.ts`)は変えない。

## 範囲

含める: 引数なしの文字列マクロ(定義と展開)と、それに伴うフロントの追随(字句解析・トラック数の数え方・入力補助キー・「記法」ヘルプ・ユーザーガイド)。

含めない:
- 引数つきのマクロ(sakuramml の `#?1`)。
- 定義済みマクロ(sakuramml の `OctaveUnison{…}` など)。
- 本体の中の `;`(トラックの区切り)と、マクロの中の定義。
- エンベロープのマクロ(下の「原典の確認結果」を参照。#499 の「音色のパラメータ」の側)。

## 原典の確認結果(2026-10-20)

#499 の文面は「同じフレーズを名前で再利用する(ffmml の `@@` マクロなど)」だったが、原典と食い違っていた。

| 方言 | 確認できた内容 | 出典 |
|---|---|---|
| MCK / ffmml | 「マクロ」は**エンベロープのマクロ**(音量・音色・ピッチ・アルペジオ・ビブラートの切り替え列)。`@01 = { 1 2 }` のように定義し、`@@01 c e g` で選ぶ。フレーズの再利用ではない。 | `mckc-e.txt`(Macros の項)、`src/macros.rs`(`VolumeMacro` `PitchMacro` など) |
| sakuramml | **文字列マクロ**: `#P1 = {cdefg}`(または `Str P1 = {…}`)で定義し、`P1` で展開する。名前は大文字で始める。引数は `#?1` `#?2`、展開時に `Foo(5)` か `Foo{5}`。定義済みマクロもある。 | `docs/syntax-macro.md`(マクロ(文字列変数)) |
| mml-iterator / tonejs-mml-to-json | マクロは無い。 | README |

分かったこと: 文字数を節約するフレーズのマクロを持つのは、確認できた範囲では sakuramml だけ。ffmml の `@@` は、フレーズの再利用ではなく、#499 の別の項目「音色のパラメータ(エンベロープなど)」にあたる。

## 決定

| 項目 | 決定 | 理由 |
|---|---|---|
| 種類 | 引数なしの文字列マクロ(文字の置き換え) | 文字数の節約が目的。引数は、規則とテストが大きく増える。 |
| 定義 | `$name={ … }`(本体は波括弧で囲む。本体の中の `{ }` は対で数える) | `$` は今は構文エラーで、保存済みの MML の意味が変わらない。sakuramml の `#名前 = {…}` に近い形。連符 `{ }n` とは、`=` の直後かどうかで区別できる。 |
| 展開 | `$name`。名前は、`$` の直後に途切れなく続く、英数字と `_` の最長の並び(空白・コメント・記号で終わる)。定義済みの名前と**完全に一致**しなければ、未定義のエラー | パーサーは空白を先に取り除くので、そのままでは名前の終わりが分からない。マクロの使用の直後だけ、空白(とコメント)を区切りとして意味のあるものにする。最長一致で定義済みの名前を探す方式は、タイプミスが黙って別の意味(`$ab` が `$a` + 音符 `b`)になる弱点があるため、採らない。 |
| 名前の文字 | 英小文字・数字・`_`(大文字は小文字として扱う。今までと同じ) | 既存の MML の「大文字小文字は区別しない」と揃える。 |
| 名前の接頭辞 | 制限しない(`$a` と `$ab` を同時に定義できる) | 名前は完全一致で決まる。 |
| 使用の直後の空白 | `$name` の直後に英数字か `_` が続くときは、空白(かコメント)で区切る(`$a c`。`$ac` は名前 `ac`)。記号(`;` `[` `]` `{` `}` `'` `<` `>` `&` `^` `.`)は、区切らなくてよい | 「空白は無視する」の、唯一の例外。 |
| 定義の空白 | `=` と `{` の前後には空白を入れてよい(`$riff = { c d }`) | 読みやすく書けるように。名前そのものの中には空白を入れられない。 |
| 定義の位置 | どこに書いても全トラックで使える(使う前に書く必要はない) | 定義を最後にまとめて書ける。展開の前に、全部の定義を集める。 |
| 入れ子と再帰 | マクロの中から別のマクロを使える。再帰(直接・間接)はエラー | 展開が止まらなくなるのを防ぐ。 |
| 本体に書けるもの | その場に置いて意味が通る MML なら何でも(`o` `l` `t` `v` `q` `@`、`[ ]`、`{ }`、`'ceg'` など)。`;` と定義は不可 | 文字の置き換えなので、制限は最小限にする。`;` は、展開でトラックが分かれる事故を防ぐ。 |
| 展開後の上限 | 展開後の文字数 100,000 文字 | マクロの入れ子で展開が膨らむ入力を抑える。5000 文字の上限には、定義も含む。 |
| 誤りの位置 | 展開された文字は元の位置を持ったままなので、本体の誤りは**定義の中のその文字**を指す | 位置の規則(元のテキストの文字位置)を変えずに済む。 |

## 構文と意味

| 書き方 | 意味 |
|---|---|
| `$riff={c d e f}` | 名前 `riff` に、本体 `c d e f` を割り当てる。定義そのものは、音を出さない。 |
| `$riff` | 本体に置き換える(展開)。 |
| `$riff 4` | 空白で名前が終わる。展開の直後の `4` は、本体の最後の音符の長さ(`c d e f4` と同じ。文字の置き換えなので)。 |
| `$riff4` | 名前は `riff4`(空白が無いので、名前の一部)。定義が無ければ未定義のエラー。 |
| `$a={c} $ab={d} $a $ab` | `$a` と `$ab` は別のマクロ(接頭辞の制限は無い)。`$a` は `c`、`$ab` は `d`。 |
| `$a={$b $b} $b={c} $a` | 入れ子。`$a` は `c c`。定義の順番は問わない。 |
| `$p={[c d]2} o3 $p o5 $p` | 本体は、展開した場所のオクターブ・音量などの状態で解釈される(文字の置き換えなので)。 |

意味の詳細:
- 展開は、コメントと空白を取り除いた後、`;` でトラックに分ける前に行う。定義(`$name={…}`)は取り除かれる。定義だけの区間(`$a={c} ; d` の `;` の前)は、空とみなされ、トラックに数えられない。
- `$` の直後に `[A-Za-z0-9_]` が途切れなく続く並びが名前(大文字は小文字として扱う)。名前の次(空白をはさんでよい)が `=` と `{` なら定義、そうでなければ展開。`$a t=60`(`$a` の展開と `t=60`)は読めるが、`$at=60` は名前 `at`(未定義)になる。
- 本体の中の位置は元のまま。`t=` や `'` を含む本体も、展開された場所で、今までの規則(`t=` の置き場所など)で検査される。

誤りと位置(0 始まりの文字位置で、エラー表示は 1 始まりの「N 文字目」):

| 入力の例 | エラー位置 | 内容 |
|---|---|---|
| `c $zzz`(未定義) | `$` | 未定義のマクロです(定義は `$名前={…}` の形で書きます) |
| `$a={c} $ab`(名前の一部になった) | `$` | 未定義のマクロ `$ab` です(`$a` を使うなら、後ろの `b` を空白で区切ってください) |
| `$a={c d`(閉じていない) | `{` | マクロの本体の `{` が閉じていません |
| `$a={c;d} $a` | `;` | マクロの中には `;` を書けません |
| `$a={$b={c}}` | 内側の `$` | マクロの中には定義を書けません |
| `$a={c} $a={d}`(二重定義) | 2 個目の `$` | マクロ `$a` は既に定義されています |
| `$a={$a} $a`(再帰) | 本体の中の `$` | マクロ `$a` が自分自身を呼んでいます |
| `$a={o9} $a`(本体の誤り) | `9`(定義の中) | オクターブは 1〜8 です(今までと同じ) |
| 展開後 100,000 文字超 | 展開していた `$` | マクロを展開した文字数が 100000 を超えました |

## 設計

Rust は `src-tauri/src/mml.rs` だけを変える。パーサーの本体(`parse_track` / `run_track`)は変えない。

- `symbols` を、コメントを取り除く段階(`strip_comments`)と、空白を取り除いて ASCII を小文字化する段階(`finish_symbols`)の 2 つに分ける(`symbols` は、この 2 つを続けて呼ぶだけになる)。`strip_comments` は、コメントを取り除いたあとに、コメントの開始位置で空白を 1 つ残す(コメントも名前の区切りとして働くようにするため)。空白はそのまま残す。
- `parse` は、`strip_comments` → 前処理 `expand_macros(chars) -> Result<Vec<(char, usize)>, MmlError>` → `finish_symbols` → `;` でのトラック分け、の順に呼ぶ。
- `expand_macros` は、空白を残した `(char, 元の位置)` の列に対して、次の順に行う。
  1. 列を先頭から読み、`$` + 名前(`[A-Za-z0-9_]+` の途切れない並び。小文字化して比べる)の次(空白をはさんでよい)が `=` と `{` なら、定義として読む。本体は、対になる `}` まで(本体の中の `{ }` は深さで数える)。定義は出力に入れず、名前と本体(空白を含む、位置つきの文字の列)を表に入れる。名前の二重定義、本体の中の `;` と定義を、ここで検査する。
  2. 定義以外の部分を出力に写し、`$` + 名前が来たら、表の名前と完全一致で探して、本体で置き換える(本体の中の `$` も、同じ規則で再帰的に展開する。展開中のマクロの名前を持ち、再帰を検出する)。展開後の文字数を数え、上限を超えたら、そのときの `$` の位置でエラー。
  3. 名前が表に無いとき(未定義)は、その `$` の位置でエラー。名前の先頭が定義済みの名前と一致するときは、「その名前を使うなら、後ろの文字を空白で区切ってください」と案内する。
- 展開された文字は元の位置を持ったままなので、パーサーの本体(`parse_track` / `run_track`)は変わらない。

フロント:
- `lib/mmlMacros.ts`(新規): 定義を見つける共有の補助関数(`findMacroDefinitions(text)`: 名前・頭(`$name=`)・本体・閉じの `}` の範囲を、元のテキストの添字(UTF-16)で返す。Rust と同じ規則: 名前は `$` の直後の途切れない `[A-Za-z0-9_]+`、次が `=` と `{`)と、定義を空白にする `blankMacroDefinitions(text)`。`blankComments` の後に使う。
- `lib/mmlUsage.ts`: `countTracks` が、`blankMacroDefinitions` も使って、定義だけの区間を数えない(Rust の展開前処理と合わせる)。
- `lib/mmlLexer.ts`: 定義の頭 `$name=` と、展開 `$name` を `command` として色分けする(名前は、`$` の直後の、元のテキストで途切れなく続く `[A-Za-z0-9_]+`。定義済みの名前を集める必要はない)。定義の本体の中身は今までどおりの色。本体の閉じの `}` は、連符の `}` と違い、後ろの数字を取り込まない。
- `lib/mmlKeys.ts`: 構造のグループに `$` のキーを足す(ソフトキーボードで切り替えが要るため)。
- 「記法」ヘルプ(`SoundChoicePicker.svelte`)とユーザーガイド(`docs/guide/user-guide.md`)に、マクロを足す。

## テスト

- Rust(`mml.rs`): 基本の定義と展開、定義の位置(使う前・後)、入れ子、同じマクロの複数回の展開、空白・大文字、`$a t=60` と `$at=60`(名前 `at`)の読み分け、`$a` と `$ab` の同時定義、`$ab`(定義済みは `$a` だけ)の未定義のエラーと案内、`$a c` と `$ac`、コメントで区切った `$a/**/c`、定義の `=` と `{` の前後の空白、本体に `o` `l` `v` `q` `@` `[ ]` `{ }` `'ceg'` `t=` を含む場合、定義だけの区間がトラックに数えられないこと、複数トラックから同じマクロを使うこと、誤り(上の表の各行)の位置、展開の上限と所要時間、マクロを含まない既存のテストが全部そのまま通ること。
- フロント(Vitest): `findMacroDefinitions` / `blankMacroDefinitions`(定義の範囲、入れ子の `{ }`、サロゲートペア)、`countTracks`(定義だけの区間)、`mmlLexer` の `$name` / `$name=` と本体、`mmlKeys` の `$` キー、ヘルプにマクロが出ること。
- 実機(手動): Xvfb と隔離したインスタンスで、マクロを含む MML の入力・色分け・エラー表示・試聴(`play_notify_sound` に渡る値)を確認する。音が鳴ることは確認できない(Xvfb に音声デバイスが無い)。

## 未確認・リスク

- 「空白は無視する」の例外が 1 つ増える: マクロの使用の直後に英数字か `_` が続くときは、空白で区切る必要がある(`$a c`)。区切らないと名前の一部になり、未定義のエラーになる(エラーが、空白で区切るよう案内する)。ガイドにも書く。
- 本体の誤りの位置は定義の中で、「どの展開が原因か」は示されない(位置の規則を変えないための決定)。
- 展開は文字の置き換えなので、本体の `{` `[` `'` が閉じていないと、展開した場所の後ろの文字を巻き込む(sakuramml も同じ)。エラーの位置は、定義の中の閉じていない記号を指す。
- 展開後 100,000 文字の上限と、既存の「展開後 50 万命令」の上限の関係: 上限いっぱいに展開した後、ループで命令数がさらに増える。所要時間はテストで確かめる。
- 他方言との互換: sakuramml の `#名前 = {…}` に近いが、書き方(`$`、名前の読み方、引数なし)は一致しない。

## 実装後の確認

2026-10-24、ブランチ `feat/issue-499-mml-macro`、実装の最後のコミット `8f3fbb1`。隔離インスタンスは、`Xvfb :97`(1280x900)、`dbus-run-session`、`XDG_*` を `/tmp` 直下の短いパスに置き、`WAYLAND_DISPLAY` を unset、`GDK_BACKEND=x11` で、`frontend/dist` を作り直してから `cargo build` した `target/debug/tsumugi` を直接起動した。ダミーのアカウント(`misskey.invalid`)だけを `settings.json` に書いた。起動した全プロセスに一意なトークンを環境変数で付け、確認のあと、トークンで特定した PID だけを止めた(Xvfb のロックファイルと隔離ホームも削除済み)。ユーザー自身の `cargo tauri dev` には触れていない。

確認できたこと:
- 自動テスト: `cargo test` は 790 件通過、失敗 0、`#[ignore]` 61 件。`pnpm check` は 0 errors(既存の `UrlPreviewCard.svelte` の警告 1 件のみ)。`pnpm test` は 98 ファイル・1061 件通過。確認後の `git status` は空(`tauri.gen.ts` は変わっていない)。
- `rustfmt --check src/mml.rs` の差分は 5 件(`main` と同じ)。
- 展開の上限と 300 段の連鎖(`macro_expansion_is_capped_and_deep_chains_work`)は 0.00 秒(基準は 1 秒)。
- 実アプリ(隔離インスタンス)。設定 → 通知 →「通知音を鳴らす」ON → 種類「MML（打ち込み）」で、エディタに `xdotool` で入力した。
  1. `$riff={c d e f} $riff $riff`: 構文エラーなし。「再生時間 4.0 秒」、文字 27/5000・音 8/3000・トラック 1/4。DOM のクラスは、`$riff=` と `$riff`(2 回)が `mml-command`、定義の `{` `}` が `mml-repeat`。
  2. `$m={c d} $m ; $m` はトラック 2/4・音 4。定義だけの区間 `$m={c d} ; $m` はトラック 1/4(音 2)で、Rust の数え方と一致した。
  3. 位置つきのエラーはすべて、保存と試聴が `disabled`。`$a={c} $ab` は 8 文字目(未定義、`$a` を使うなら後ろの `b` を空白で区切る案内つき)、`c $zzz` は 3 文字目(未定義)、`$a={$a} $a` は 5 文字目(自分自身)、`$a={o9} $a` は 6 文字目(オクターブは 1〜8)、`$a={c;d} $a` は 6 文字目(`;` を書けない)。「N 文字目」を押したあとに印を打ち、それぞれ指示された文字の直前にカーソルが移ることを確かめた。
  4. `$a={c} $a d` は構文エラーなし(文字 11・音 2・トラック 1)。`$a={c} $ad` は 8 文字目の未定義のエラーで、保存・試聴が `disabled`。
  5. 「記法」に、`$riff={c d e f} マクロ(文字の置き換え)。…名前の直後に英数字が続くときは空白で区切る($riff 4)。…` の行が、`$` と波括弧が文字のまま出た。
  6. 1 の MML で「試聴」を押すと、`play_notify_sound` に `data:audio/wav;base64,…`(270,571 文字)が渡った(`fetch` の `ipc://` を包んで記録)。手で展開した `c d e f c d e f` の試聴で渡る値と、1 文字も違わず一致した。

- 入力補助キー `$` の、モバイル UI での実際の押下(自動テストの `SoundChoicePicker.keys.test.ts` が全キーを押すところまで)。
