# モバイル版: 左右スワイプでタブ/カラムを移動する (Issue #296)

## 背景

現状モバイル版(`useMobileUi()`が`true`のとき)は、カラム全体をネイティブの横スクロール
(`overflow-x-auto`)で移動でき、タブはタブバーをタップして切り替えている。Issue #296 では、
左右スワイプでタブ送りができるようにしたい、というリクエストがある。Issue本文にある案
「タブを送り、タブの端まで来たらカラムを移動する」を採用する。

## スコープ

- 対象は`useMobileUi()`が`true`の場合のみ。デスクトップUIの挙動は変更しない。
- 対象コンポーネントは`Column.svelte`のノート/通知一覧エリア。
- 「カラムの並び」は**最上位rowの直下の子のうちtype: "leaf"のものだけ**を対象にする。
  ネストした`split`(下方分割/右方分割で作られた入れ子)配下のカラムはスワイプでの
  カラム間移動の対象外とする。モバイルの狭い画面幅では分割はそもそもあまり想定されておらず、
  スコープを最上位の横並びに限定することで実装・検証コストを抑える。

## 挙動

1. タブが2つ以上あるカラムで左右スワイプすると、タブを送る(次/前のタブをアクティブにする)。
2. 現在のタブがそのカラムの先頭/末尾タブで、さらに同方向にスワイプすると、次/前のカラムへ
   移動する。移動先カラムのアクティブタブは、そのカラムの現在の`activeTabId`をそのまま使う
   (タブ位置を揃えたりはしない)。
3. タブが1つしかないカラムでは、スワイプは直接カラム移動として働く。
4. 移動先が存在しない(先頭カラムの先頭タブでさらに前へ、末尾カラムの末尾タブでさらに次へ)
   場合はスワイプ自体を無効化する。

## UI/アニメーション

- ネイティブアプリのタブ送りに近い、追従ドラッグ+アニメーションスワイプを採用する。
- ドラッグ中は指の動きにコンテンツが追従し(`translateX`)、指を離した時点の移動量/速度が
  閾値を超えていれば残りをアニメーションで滑らせて確定、超えなければ元の位置へ
  スプリングバックする。
- 移動先が存在しない端では、ドラッグ量を減衰させて抵抗感(rubber-band)を出す。
- ドラッグ中は「現在の内容」と「移動先の内容」の2枚を並べてDOM上に描画し、
  ラッパー全体を`translateX`することで実際にスワイプしている見た目にする。

## ジェスチャー検知

- ノート一覧の`<div class="flex-1 overflow-y-auto">`に`pointerdown/move/up`ハンドラを追加する。
  `useMobileUi()`が`false`のときはハンドラを付けない。
- CSSに`touch-action: pan-y`を設定し、ブラウザ標準の縦スクロールは温存しつつ、横方向の
  ジェスチャー判定はJS側で行う。
- ポインタ移動量が一定(例: 10px)を超えた時点で、横移動量が縦移動量より優位なら
  「横スワイプ」と判定してドラッグモードに入り、以降そのポインタが離れるまで
  `preventDefault`してネイティブスクロールを止める。縦移動が優位なら何もせず通常の
  縦スクロールに任せ、以降そのポインタでは横スワイプ判定を再度行わない
  (一度モードが確定したらそのポインタが離れるまで固定)。

## 状態遷移

- タブ切替(`setActiveTab`相当)やカラム移動(`focusedGroupId`更新、該当カラムへのスクロール)は、
  ドラッグ完了(確定)時にのみ行う。ドラッグ中の中間状態では呼ばない。
- 「次/前のタブ」「次/前のカラム」を解決するロジックは、`app.paneRoot`(ペイン分割ツリー)と
  `app.groups`(視覚カラムの集合)を横断する必要があるため、`store.svelte.ts`の`AppStore`に
  薄いAPI(例: `swipeNextTab(tabId)` / `swipePrevTab(tabId)`、あるいは移動先を返す純粋な
  解決関数)として実装し、`Column.svelte`から呼び出す。
- Backstage/モーダル/リアクションピッカーなど他のオーバーレイが開いている間や、既存の
  タブ/カラムのドラッグ&ドロップ操作(`app.draggingTabId`/`app.draggingGroupId`)が進行中は
  スワイプジェスチャーを無効化する。

## テスト方針

- ジェスチャー判定の閾値ロジック(縦横判定、確定判定、次/前のタブ・カラムを解決する関数)は
  純粋関数として切り出し、Vitestでユニットテストする。
- 実際のpointerイベント統合やアニメーションはブラウザ依存が強く、既存のe2e(`e2e/`)は
  デスクトップ想定のtauri-driver構成のため、本Issueのスコープでは新規E2E追加は行わず、
  Android実機での手動確認を最終確認とする。

## 非スコープ

- ネストした分割(split)配下のカラム間でのスワイプ移動。
- デスクトップUIでのスワイプ対応。
